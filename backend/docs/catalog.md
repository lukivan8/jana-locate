# Каталог зданий и эксплуатация

## Формат и идентичность

Начальный `data/catalog.seed.json` и записываемый overlay имеют формат `{"entries":[...]}` из OpenAPI. Локальный overlay — `var/catalog.confirmed.json`, в Docker — `/data/catalog.confirmed.json`.

Включённый seed синтетический: `revision: 0`, `confirmed: false`, явная маркировка источника. Заменяйте его только проверенными данными с подходящими правами использования. Квартиры, подъезды, этажи и ориентиры не входят в значения здания по умолчанию.

ID вычисляется из города, типа улицы, названия улицы и дома: нормализация регистра/пробелов и первые 12 байт SHA-256. ID из файла пересчитывается при загрузке. Варианты регистра и пробелов совпадают; переименования, транслитерация и псевдонимы автоматически не объединяются. Дроби дома сохраняются. Дубликаты структурного ключа внутри файла отклоняются; overlay перекрывает seed по ключу.

## Конкурентность и сохранение

Один процесс владеет одним overlay. Потоки защищены mutex; независимые процессы не имеют общей блокировки и не должны писать в один файл.

Обновление проверяет ожидаемую ревизию, пишет отсортированный снимок во временный файл на той же файловой системе, выполняет fsync файла и атомарный rename. Память обновляется только после успешной записи. Повреждённые каталоги останавливают запуск. Подтверждения сохраняются при обычном рестарте.

Каталог директории не fsync-ится, поэтому внезапная потеря питания не входит в гарантию долговечности. Запись занимает O(числа подтверждений). Истории изменений и аудита пользователей нет. Для распределённых записей или большого каталога понадобится транзакционное хранилище.

## Изменения

- Начальные здания: измените seed, проверьте и пересоберите образ. Seed читается при запуске.
- Подтверждённые пользователем данные: используйте API подтверждений.
- Новое здание: ревизия 0; существующее: актуальная ревизия.
- Изменение структурного ключа создаёт отдельную запись; старое здание остаётся.
- Для удаления/переименования остановите сервис и согласованно мигрируйте seed и overlay. API удаления нет.

Не редактируйте overlay работающего процесса. Полная адресная строка и входной ID не используются для поиска сохранённого ответа. Детали доставки разбираются заново.

## Резервное копирование Docker-тома

Команды соответствуют контейнеру и тому из README. Остановите единственный процесс записи и скопируйте снимок:

```sh
docker stop jana-address
mkdir -p backups
docker run --rm --user 10001:10001 \
  -v jana-address-catalog:/data:ro --entrypoint cat \
  jana-address:local /data/catalog.confirmed.json > backups/catalog.confirmed.json
docker start jana-address
```

При отсутствии подтверждений файла ещё может не быть; ошибка `cat` в этом случае означает, что копировать нечего. Храните резервные копии вне Git и с ограниченным доступом.

Восстановление выполняйте только при остановленном процессе:

```sh
docker stop jana-address
docker run --rm -i --user 10001:10001 \
  -v jana-address-catalog:/data --entrypoint sh jana-address:local \
  -c 'cat > /data/catalog.confirmed.json' < backups/catalog.confirmed.json
docker start jana-address
```

Проверьте файл до восстановления; повреждённый JSON остановит запуск. Восстановление старой копии намеренно откатывает подтверждения. Удаление Docker-тома удаляет данные. Smoke-тесты всегда запускайте с отдельным временным томом.

## Неизменяемый справочник

SQLite КАТО/OSM хранится отдельно, не имеет координат зданий и открывается read-only. Подтверждения никогда не записываются в него. Подробности: [справочник](reference.md).
