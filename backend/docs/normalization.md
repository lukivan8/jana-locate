# Нормализация и модели

## География и язык ввода

Текущая география адресов — Казахстан. Пользователь может писать на русском,
казахском, кыргызском, узбекском, таджикском, монгольском, транслитом или смешивать
письменности. Язык не выбирает страну доставки и не меняет административную
иерархию Казахстана. Иностранные названия внутри ориентиров/инструкций не
становятся населёнными пунктами назначения. Языковые примеры предназначены
для будущего улучшения модели; это не утверждение поддержки всех языков
текущей реализацией.

## Последовательность

1. Исходная строка и ID сохраняются. Для обработки создаётся копия с нормализацией выбранных невидимых символов и пробелов.
2. Native libpostal выполняет первый проход. Инициализация происходит один раз; обращения сериализованы из-за глобального состояния C-библиотеки. Компоненты привязываются к исходным текстовым фрагментам.
3. Правила независимо выделяют явные маркеры, слитные числа, дроби, литеры и детали доставки.
4. Неизменяемый КАТО/OSM добавляет кандидатов с учётом псевдонимов и иерархии. Снимок Казахстана содержит отдельные свидетельства улицы/дома: точный адрес может уточнить один из уже упомянутых одноимённых населённых пунктов. Ограниченное покрытие OSM не позволяет вывести город только по единственной найденной улице; неизвестные адреса не исключаются на основании отсутствия в справочнике.
5. Go согласует значения по полям. Сильные явные маркеры приоритетнее слабых догадок модели; близкие противоречивые гипотезы не выбираются произвольно.
6. Определяются полнота основных адресных полей и неоднозначности. Каталог зданий не читается, геокодирование не выполняется.
7. `confidence` учитывает свидетельства, согласие, полноту, конфликты и доступность libpostal. Это эвристика для проверки, а не калиброванная вероятность.

Написание выделенной улицы остаётся привязанным к вводу; справочник помогает сопоставлению, а не подменяет исходную строку. Устаревшие `coordinates`, `catalog_id`, `catalog_revision` сохраняются в ответе для совместимости и всегда равны `null`. Они не влияют на поля, confidence или статус.

## Сохранение неоднозначности при обучении и разборе

Явная подсветка неоднозначности — корректный результат нормализации. LLM при
разметке может выбрать предпочтительную гипотезу; этот выбор не даёт оснований
удалять альтернативы или требовать от нормализатора единственного ответа.

Извлечение компонента и выбор справочной сущности — разные задачи. `city`
означает населённый пункт любого типа. `Караганда` может быть уверенно извлечена
как текст, но локальный КАТО содержит отдельно село `kato:154247300` и город
`kato:351010000`. При недостатке различающего контекста следует сохранять
совместимые кандидаты, `ambiguous_city_reference` и статус проверки. Известность
города или частота его появления в синтетике не устраняют существование села.

Разметка фрагментов, её закрытый `review` и ID основы генерации не являются
эталоном уникальной географической идентичности. Их нельзя использовать для
обучения подавлению предупреждений или обязательному выбору исходного объекта.
Кандидаты уточняются по свидетельствам текущего ввода и совместимым справочным
фактам либо явному выбору оператора. Неполнота справочника учитывается отдельно.

Для будущего обучения необходимы случаи омонимов с различающим контекстом
и без него. Оценка должна учитывать сохранение неоднозначности и ложные
уверенные решения отдельно от точности извлечения; допустимая неоднозначность
не считается ошибкой только из-за несовпадения с выбранной LLM гипотезой.

Район извлекается из текста либо дополняется по точному дому, полному покрытию
наблюдаемой геометрии улицы или иерархии КАТО. Явный конфликт сохраняется,
неоднозначное или неполное покрытие не даёт уверенного назначения. Источники
и предупреждения описаны в [определении района](district-reference-plan.md).

## libpostal

Dockerfile закрепляет commit `25099c506612b34b23b1bfe286ca6321fcf06f35` и скачивает base/parser во время сборки. Запуск не скачивает модели. Для ручной native-сборки нужны C-компилятор, установленная libpostal и подготовленные assets:

```sh
CGO_ENABLED=1 \
CGO_CFLAGS=-I/opt/libpostal/include \
CGO_LDFLAGS='-L/opt/libpostal/lib -Wl,-rpath,/opt/libpostal/lib' \
LIBPOSTAL_DATA_DIR=/models/libpostal \
REFERENCE_PATH="$PWD/data/reference/reference.sqlite" \
MODELS_REQUIRED=true \
  go run -tags libpostal ./cmd/server
```

Обычная сборка без тега использует fallback и выдаёт `libpostal_unavailable`. Она позволяет тестировать API без установки C-библиотеки.

## Режимы и ограничения

- Без native libpostal: правила и необязательный SQLite-справочник; результат содержит `libpostal_unavailable`.
- Полный режим: native libpostal, правила и адресный справочник. Подготовленные assets находятся локально; runtime не обращается к внешним моделям и не требует Python-сервиса.
- `MODELS_REQUIRED=true` проверяет наличие libpostal при старте. При `false` разрешён явно помеченный резервный разбор.

Legacy-каталог содержит явно помеченные синтетические здания. `ALLOW_DEMO_CATALOG` не влияет на текущую нормализацию; новые результаты не получают координат из каталога. Скорость на синтетических fixtures не измеряет качество разбора реальных адресов.

House markers accept `д12`, `д 12`, `д.12`, `д. 12`, `дом12` and `дом 12` at a token boundary. If libpostal omits the street beside a glued explicit house marker, reconciliation can recover a complete comma-separated street alias from the local directory before resolving a settlement by positive street+house evidence. Partial street aliases are insufficient; exact raw strings are preserved. Native regression: set `LIBPOSTAL_TEST_DATA` and `REFERENCE_TEST_PATH` to prepared assets, then run `go test -tags libpostal ./internal/normalize -run TestNativeHouseMarkers -v` with the normal native build flags.


## Статус без геокодирования

`matched` означает нормализованный адрес: определены область, город, улица и дом, confidence не ниже 0.72, нет ambiguous/conflicting diagnostics. `needs_review` — неполный или неоднозначный разбор; `unmatched` — нет извлечённых адресных полей. Квартира, этаж, подъезд и район не обязательны при отсутствии в строке. Оценка уверенности остаётся эвристической, не вероятностью точности. Отсутствие координат не создаёт предупреждение и не направляет запись оператору.

Каталог зданий и его прежние endpoints сохраняются отдельно для совместимости. Их подтверждения, координаты и синтетические записи не участвуют в нормализации. Сохранённые ранее задания остаются историческими снимками; для получения нового поведения нужно создать новый пакет.

## Удаление второго прохода

GLiNER удалён из runtime и конфигурации. Новые результаты не получают `gliner_unavailable` и связанный с ним штраф 0.95 к confidence. Остальные коэффициенты confidence, правила полноты и проверки конфликтов сохранены. Исторические задания и локальные журналы CLI не пересчитываются и не мигрируют автоматически. Публичный формат HTTP API не изменился.
