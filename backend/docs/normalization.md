# Нормализация и модели

## Последовательность

1. Исходная строка и ID сохраняются. Для обработки создаётся копия с нормализацией выбранных невидимых символов и пробелов.
2. Native libpostal выполняет первый проход. Инициализация происходит один раз; обращения сериализованы из-за глобального состояния C-библиотеки. Компоненты привязываются к исходным текстовым фрагментам.
3. Правила независимо выделяют явные маркеры, слитные числа, дроби, литеры и детали доставки.
4. Внутренний CPU GLiNER получает рабочие тексты пакетами по 32. Пустые строки пропускаются; длинные разбиваются на перекрывающиеся окна. Смещения — кодовые точки Unicode, проверяемые в Go.
5. Неизменяемый КАТО/OSM добавляет кандидатов с учётом псевдонимов и иерархии. Ограниченное покрытие OSM не позволяет вывести город только по единственной найденной улице.
6. Go согласует значения по полям. Сильные явные маркеры приоритетнее слабых догадок модели; близкие противоречивые гипотезы не выбираются произвольно.
7. Единственное совместимое здание может дополнить структуру и координаты. Детали доставки из каталога не заполняются.
8. `confidence` учитывает свидетельства, согласие, полноту, конфликты и недоступные модели. Это эвристика для проверки, а не калиброванная вероятность.

Написание выделенной улицы остаётся привязанным к вводу; справочник помогает сопоставлению, а не подменяет исходную строку. При неопределённости координаты остаются `null`.

## libpostal

Dockerfile закрепляет commit `25099c506612b34b23b1bfe286ca6321fcf06f35` и скачивает base/parser во время сборки. Запуск не скачивает модели. Для ручной native-сборки нужны C-компилятор, установленная libpostal и подготовленные assets:

```sh
CGO_ENABLED=1 \
CGO_CFLAGS=-I/opt/libpostal/include \
CGO_LDFLAGS='-L/opt/libpostal/lib -Wl,-rpath,/opt/libpostal/lib' \
LIBPOSTAL_DATA_DIR=/models/libpostal \
REFERENCE_PATH="$PWD/data/reference/reference.sqlite" \
GLINER_URL=http://127.0.0.1:8090 MODELS_REQUIRED=true \
  go run -tags libpostal ./cmd/server
```

Обычная сборка без тега использует fallback и выдаёт `libpostal_unavailable`. Она позволяет тестировать API без установки C-библиотеки.

## GLiNER

В этом репозитории находится только Go-клиент. Подготовленный сервис доступен в [nlp полного проекта](https://github.com/lukivan8/jana-locate/tree/main/nlp). Он использует CPU, GLiNER 0.2.22 / PyTorch 2.6.0, `urchade/gliner_multi-v2.1` revision `443d26d654e0324125a96bebd8e796c14ff2efe6`, микропакеты 8 и обычно два потока. Локальные веса и tokenizer готовятся до запуска; offline-переменные запрещают загрузку во время работы.

Сервис должен быть доступен по `GLINER_URL`. Проверка готовности: `GET /readyz`. Запросы и ответы второго прохода реализованы в [`internal/normalize/gliner.go`](../internal/normalize/gliner.go); это внутренний протокол, а не публичный API приложения. GLiNER нельзя предоставлять браузеру напрямую.

При `MODELS_REQUIRED=true` неготовые модели останавливают запуск. При необязательных моделях результаты содержат предупреждения, без скрытого улучшения оценки. Многоязычный NER не является специально обученной моделью адресов Казахстана; точность необходимо измерять на независимых данных.

## Режимы и ограничения

- Без моделей: разработка API, правила и необязательный SQLite-справочник.
- Native libpostal без GLiNER: первый проход и правила, явно ограниченный второй проход.
- Полный режим: обе модели, справочник и каталог зданий; runtime без интернета.

Синтетические здания отключены по умолчанию. Для демонстрации задайте `ALLOW_DEMO_CATALOG=true`: появится `synthetic_catalog_coordinates`, статус проверки и ограниченная уверенность. Для оценки используйте `false` и чистый либо раскрытый каталог подтверждений. Скорость на синтетических fixtures не измеряет качество разбора реальных адресов.
