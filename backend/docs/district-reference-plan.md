# Район из текста и адресного справочника

Реализовано офлайн-обогащение района по подготовленным связям КАТО/OSM.
HTTP API сохраняет прежний формат: значение возвращается в `district`,
источник и неоднозначность обозначаются предупреждениями.

## Подготовленные данные

Исходные сущности и адресные факты сохранены. Отдельный `districts.jsonl.gz`
содержит отношения для 528 252 адресных объектов и 20 883 улиц, подготовленные
по 168 сопоставленным административным полигонам. Четыре спорных полигона
пропущены. Из 549 135 объектов 538 758 имеют полное покрытие наблюдаемой
геометрии; 668 имеют несколько районных кандидатов. Это покрытие текущего
снимка OSM, а не гарантия полноты реальной улицы или ручной проверки здания.

Районы Астаны и Тұран Шымкента в КАТО имеют исходный тип `admin`.
Адаптер признаёт район по роли в иерархии и каноническому имени источника,
сохраняя исходный тип. Сельские округа автоматически районами не становятся.

Полигоны сопоставляются с КАТО по именам, области и родительскому городу.
Для адресных nodes используется точка; для замкнутых адресных ways — полигон
здания. Для улицы проверяются все наблюдаемые сегменты полной линии.
Пересечение границ сохраняет множество районов; принадлежность не назначается
по центру здания или средней точке улицы. Пропущенная геометрия совместимого
одноимённого объекта блокирует уверенный вывод по улице.

Отношения хранятся в схеме SQLite версии 3, отдельно от исходных сущностей,
с идентификаторами кандидатов, источником и полнотой покрытия. Координаты
не экспортируются. Runtime загружает индекс в память и не выполняет
пространственных операций, SQL-запросов, сетевых запросов или второго NLP-прохода.

## Согласование во время запроса

| Доступное свидетельство | Поведение |
| --- | --- |
| Однозначный населённый пункт, улица, точный дом и единственный район | Дополнить район по адресному факту |
| Полная наблюдаемая геометрия улицы внутри одного района | Дополнить район по улице, в том числе без известного дома |
| Улица пересекает районы, точный дом неизвестен | Район неизвестен; `ambiguous_district_reference` |
| Есть лишь отдельные дома улицы в одном районе | Не считать это доказательством района всей улицы |
| Точка на границе или здание пересекает границу | Сохранить неоднозначность |
| Явный район противоречит справочному | Сохранить явный компонент и `conflicting_district` |
| Явный район несовместим с городом/областью | Сохранить его и `conflicting_district_context` |
| Несколько разных явно названных районов | Район неизвестен; конфликт |
| Покрытие геометрии неполное | Район неизвестен; `district_coverage_incomplete` |
| Однозначная принадлежность населённого пункта району КАТО | Дополнить район по иерархии КАТО |
| Нет подходящих данных | Оставить район неизвестным |

Положительный результат получает `district_inferred_from_address`,
`district_inferred_from_street` или `district_inferred_from_kato`.
Номера домов сравниваются целиком, включая дроби и литеры; соседние номера,
чётность и частота синтетических примеров не используются для интерполяции.
Точный дом имеет приоритет над отношением всей улицы. Неполнота любого
совместимого одноимённого объекта блокирует уверенное геометрическое назначение.
Отсутствие района само по себе не мешает статусу `matched`.

Явные районы проверяются по справочнику и административному контексту;
роли улицы и ориентира учитываются, чтобы их названия не стали районом.
Справочное извлечение без поддержки NLP ограничено самостоятельным компонентом
строки. Произвольный текст и отрицание не интерпретируются по одному совпавшему
имени. Новая мультиязычная модель этой доработкой не обучается.

Район может уточнить уже упомянутые одноимённые населённые пункты через
положительную иерархию КАТО. При недостатке свидетельств город/село остаются
альтернативами. Закрытая LLM-разметка и ID синтетического источника не выбирают
справочную идентичность. Неоднозначность — корректный результат нормализации.

## Проверка и обновление

Тесты отдельно проверяют геометрию, полноту, конфликт, названия внутри улицы
и ориентира, омонимы населённых пунктов, адаптацию `admin` и чтение схем 1/2.
Старые снимки позволяют дополнить сельский район по КАТО, но не выдумывают
геометрию внутригородских районов. Сборщик проверяет ссылки и контрольные суммы,
атомарно заменяет SQLite; при ошибке предыдущий файл сохраняется.

Для применения подготовленного снимка пересоберите SQLite/образ и перезапустите
backend. Уже сохранённые задания не пересчитываются: создайте новый пакет.
Синтетические fixtures проверяют поведение, а не точность реальных адресов.
