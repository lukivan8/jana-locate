# Contextual v7 runtime

Автономный кандидат: общий контекстный encoder, BIO head v7, native libpostal numeric evidence,
ограниченный microdistrict head и неизменяемые KATO/OSM справочники. Последний экспериментальный
ранжировщик не включён. Runtime не читает разметку, исходные ID или полные адреса для поиска ответа.

## Артефакты и сборка

`assets/` не входит в Git. Это выпускной пакет из проверенного кандидата; точный состав и SHA-256
зафиксированы в `assets-manifest.json`. Сборка проверяет каждый файл. Веса голов не воспроизводятся
одной установкой зависимостей: для новой машины требуется этот выпускной пакет. Его отсутствие
останавливает сборку, runtime ничего не скачивает. Не подменять веса новыми без повторного сравнения.

Базовый образ `jana-contextual-base:v7` для этого выпуска зафиксирован из проверенного окружения
`sha256:5f507178b1ad5b98250c3cb41f278831ab963e00ef70676bae3e5ec85b16157d`.
В финальный образ копируются только Python зависимости, native библиотека, native parser и его модели;
лабораторные результаты не копируются. Рецепт повторной подготовки базы: сначала собрать `postal`
из backend/Dockerfile как `jana-postal-assets:v1`, затем `docker build -f Dockerfile.base -t
jana-contextual-base:v7 .`. Переустановленная база требует проверки эквивалентности.

Из этого каталога: `docker build -t jana-contextual:v7 .`.
Из корня: `docker compose -f compose.yaml -f compose.contextual.yaml up --build --wait`.
Для showcase используется также compose.showcase.yaml, сеть runtime изолирована от интернета.
Без compose.contextual.yaml обычный backend продолжает использовать native baseline.

## Контракт и эксплуатация

В Go API задаётся `CONTEXTUAL_NORMALIZER_URL=http://contextual:8080`. Сам Go процесс тогда не загружает
вторую копию native модели. `/readyz` проверяет доступность inference. Один inference запрос выполняется
за раз, ещё до трёх ждут в ограниченной очереди (не более 150 секунд ожидания). При переполнении
возвращается 503. Для уже выполненного задания список городов читается из его сохранённых доказательств. Новый
запрос нормализации всегда вычисляется заново: ответов по строке/ID нет.
Readiness обслуживается отдельно.
Фоновое задание при сбое становится failed, синхронный запрос возвращает 503; ошибочный пустой разбор
не записывается как успешный. Бюджет Go вызова 270 секунд, контейнер 2 CPU / 4 GiB.

`normalizer_version` идентифицирует выпуск. `confidence_available=false`, `confidence=0` означает
отсутствие откалиброванной оценки, а не нулевую вероятность. Все автоматические результаты пока
`needs_review`. `normalization_details` сохраняет исходные spans (Unicode code points), альтернативы,
кандидатов и диагностику. Общая отображаемая форма названия не выбирает справочную идентичность.
Явный выбор оператора записывается отдельно, альтернативы остаются в доказательствах.

Сырые адреса не логируются. Не публиковать рабочие volumes или резервные копии. Поле details может
увеличивать размер ответа; клиентам не нужно отображать его целиком.

Проверка UI на временном API: `JANA_TEST_CONTEXTUAL=1 JANA_TEST_API_URL=... JANA_TEST_WEB_URL=...
npm run test:e2e -- --config playwright.contextual.config.ts tests/contextual.spec.ts` из frontend.
Конфигурация увеличивает только время ожидания inference; проверки полей и экспорта не ослаблены.
