# Как внести изменение

Спасибо за интерес к Jana Locate. Основной репозиторий для кода, документации, issues и pull requests — этот проект.

## Ошибка или предложение

Откройте [issue по шаблону](https://github.com/lukivan8/jana-locate/issues/new/choose). Для ошибки укажите commit, способ запуска, режим парсера, минимальный синтетический ввод, фактический и ожидаемый результат. Объясните, на каком основании снимается неоднозначность. Не публикуйте реальные адреса клиентов, ID заказов, пароли, токены и рабочие журналы.

Уязвимости сообщаются отдельно: [SECURITY.md](SECURITY.md).

## Локальная разработка

Нужны Go 1.23+, Node.js 22.12+, Python 3; для контейнерных проверок — Docker Engine и Compose v2. [Запуск окружения](docs/quickstart.md).

Прочитайте корневой и соответствующий приложению `AGENTS.md`. Backend, frontend и CLI собираются независимо. До изменения интерфейса изучите [M3-подход](frontend/docs/material-design-3.md).

```sh
make reference
make check
```

Для изменения нормализационного контракта сначала правьте `backend/api/openapi.json`, затем выполните `make generate` и `make check`. CLI владеет отдельным контрактом локальной оркестрации. Сгенерированные DTO не редактируются вручную.

## Что проверять

| Изменение | Проверки |
| --- | --- |
| Документация и примеры | `python3 scripts/check-docs.py`; запустить затронутые примеры против временного API |
| Backend или CLI | Race-тесты и vet соответствующего приложения; `make check` перед передачей |
| Контракты | `make generate`, `make check`, просмотр сгенерированных diff |
| Docker и хранение | `make smoke`; для CLI — `make cli-smoke` |
| Обещание offline | `make offline-smoke` на заранее собранных образах |
| Интерфейс | Build/typecheck, Playwright и браузерная проверка desktop + 390×844 |

Для Playwright используйте временное хранилище API, точный CORS origin и параметры `JANA_TEST_API_URL`/`JANA_TEST_WEB_URL`. Никогда не направляйте тесты подтверждений и сохранения на рабочий том. Подробности в [frontend README](frontend/README.md).

## Принципы результата

- Сохранять входной порядок, ID и точную исходную строку.
- Оставлять неизвестные поля `null` и сохранять совместимые географические гипотезы.
- Не считать LLM-разметку, популярность города или ID синтетической основы доказательством уникальной сущности.
- Не добавлять кеш готовых ответов по полному адресу/ID.
- Не превращать квартиру, этаж, подъезд или ориентир в свойства здания по умолчанию.
- Не добавлять runtime-загрузки моделей, онлайн-геокодеры и межкаталожные зависимости приложений.

## Pull request

Опишите пользовательскую проблему, итоговое поведение, проверки и ограничения. Для визуального изменения приложите скриншоты desktop/mobile. Для изменения данных приложите происхождение, manifest и сведения о покрытии. Не включайте `.env`, операционные overlays, SQLite-журналы, дампы и приватные документы.

Одна задача на PR помогает проверить изменение. Собственный вклад публикуется под MIT с сохранением условий сторонних материалов. [Правила общения](CODE_OF_CONDUCT.md).
