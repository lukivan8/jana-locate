# Jana Locate — веб-интерфейс

Самостоятельное приложение TanStack Start в режиме SPA. Пользователь загружает адреса, проверяет результаты, исправляет поля и экспортирует JSON. Для подключения к API нужны только публичный URL и HTTP-контракт.

[Основная страница](../README.md) · [Работа в браузере](../docs/web.md) · [Руководство интеграции](../docs/integration.md)

## Готовая установка

Для локальной работы используйте [готовые контейнеры](../docs/quickstart.md): `web` запускает автономный API и frontend, `full` — API и CLI со встроенным frontend. Для локального интерфейса с hosted API выберите `hosted`. Онлайн-приложение: [jana.linker.kz](https://jana.linker.kz).

## Разработка

Из этого каталога, Node.js 22.12+:

```sh
npm ci
VITE_JANA_API_URL=http://localhost:8080 npm run dev
npm run build
npm run typecheck
```

API запускается отдельно. Приложение собирается без Go-исходников, работающего API и соседних каталогов. Нет BFF/server functions или запросов к API при prerender оболочки.

## Сборка Docker-образа для разработки

```sh
docker build -t jana-address-web:local .
docker run --rm -p 127.0.0.1:3000:8080 \
  -e JANA_API_URL=http://localhost:8080 jana-address-web:local
```

Production содержит статические файлы `dist/client` и Nginx, без Node-процесса. Переходы по прямым ссылкам используют SPA-shell. `JANA_API_URL` при старте записывается в `/config.js`; это URL для браузера, поэтому Docker-имя `backend` обычно не подходит. API должен разрешать точный origin интерфейса. Для HTTPS сайта используйте HTTPS API.

В dev используется `VITE_JANA_API_URL`, затем `http://localhost:8080`. В конфигурацию браузера нельзя помещать секреты.

## Контракты

`src/api/openapi.json` — явно принятый снимок API нормализации, `src/api/local-openapi.json` — снимок локальной CLI-оркестрации. TypeScript-типы генерируются закреплённым инструментом. `openapi-fetch` проверяет типы вызовов при сборке; это не runtime-валидатор ответа.

Принять контракт запущенного API:

```sh
JANA_API_URL=http://localhost:8080 npm run contract:pull
npm run contract:generate
npm run build
npm run typecheck
```

В полном репозитории используйте `make generate` и проверяйте diff. Во время обычной сборки скачивания контракта нет.

## Состояние и проверка

Пакет сохраняется на API как задание; исправления хранятся отдельно от исходных записей. Ссылка восстанавливает сохранённое задание после обновления страницы. Несохранённые черновики не являются постоянным хранилищем. [Сроки, ревизии и конфликты](../backend/docs/jobs.md).

В CLI-режиме тот же frontend работает с локальным журналом и PostgreSQL. Профиль БД остаётся на CLI-сервисе; браузер не получает сохранённый пароль. Готовый frontend включается в бинарник CLI командой `node scripts/build-cli-web.mjs` из корня проекта.

Для проверки нужен API с временным overlay/хранилищем и разрешённым тестовым origin:

```sh
npx playwright install chromium
JANA_TEST_API_URL=http://localhost:8080 npm run test:e2e
```

`JANA_TEST_WEB_URL` задаёт отдельный адрес интерфейса. Не направляйте тесты на рабочие данные. Визуальные изменения проверяются в браузере на desktop и 390×844, включая нужный сценарий, ошибки и console.

## Дизайн и примеры

Следуйте [Material Design 3](docs/material-design-3.md), используйте `src/ui/material.tsx` и семантические токены. `npm run theme:generate` обновляет палитру из зелёного seed; внешние шрифты и runtime-сервисы для оформления не нужны.

Встроенные сложные адреса синтетические. Они иллюстрируют варианты ввода, но не являются проверенным эталоном качества. Явные неизвестные поля и предупреждения сохраняются. Геокодирование в текущую нормализацию не входит.
