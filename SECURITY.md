# Безопасность

## Сообщить об уязвимости

Используйте [закрытое сообщение об уязвимости в GitHub](https://github.com/lukivan8/jana-locate/security/advisories/new). Не создавайте публичный issue с работающим способом доступа к чужим данным или секретами.

Укажите затронутый commit, компонент, условия воспроизведения, ожидаемое воздействие и синтетический пример. Пароли, токены и реальные адреса не прикладывайте. Срок ответа и отдельные сроки поддержки версий пока не установлены; это не обещание круглосуточного сопровождения.

## Границы текущей реализации

- API нормализации не имеет встроенной авторизации. По умолчанию порты Compose привязаны к loopback; для внешнего доступа нужен защищённый шлюз.
- CORS не является механизмом аутентификации.
- Серверные задания и локальный CLI-журнал содержат введённые адреса и правки. Ограничивайте доступ к файлам, томам, резервным копиям и ссылкам на задания.
- CLI хранит профиль PostgreSQL локально и не передаёт пароль нормализатору. Нормализатор получает адресные строки.
- Демонстрационный пароль CLI необходимо заменить; публичное демо должно работать только с синтетическими данными.
- Один процесс должен владеть одним рабочим файловым хранилищем. Совместная запись нескольких реплик не поддерживается.

[Практические настройки развёртывания](docs/deployment.md). Поддерживаемая исходная версия — актуальная ветка `main`; отдельная политика LTS пока не объявлена.
