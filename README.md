# Jana Locate

**Адреса Казахстана → структурированные поля → проверка спорных записей → JSON.**

Jana Locate выделяет населённый пункт, область, район, улицу, дом и детали доставки из свободного текста. Сервис сохраняет исходный ввод, показывает неизвестные поля и предлагает оператору разрешить неоднозначность. Подключается к вашему приложению по HTTP; после подготовки локальных образов работает без интернета и внешних AI API.

[**Попробовать на сайте ↗**](https://jana.linker.kz/geocoder) · [Скачать и запустить](#скачать-и-запустить-v020) · [Отправить batch-запрос](#первый-batch-запрос) · [Документация](docs/README.md)

## Первый запуск на сайте

Установка и регистрация не нужны.

1. Откройте [разбор одного адреса](https://jana.linker.kz/geocoder).
2. Вставьте строку ниже и нажмите **«Разобрать адрес»**.
3. Сравните выделенные поля с исходной строкой.

```text
Павлодар, улица Тестовая, дом 73; 41 пәтер; 2 кіреберіс; 4 қабат
```

| Поле | Результат |
| --- | --- |
| Область / населённый пункт | Павлодарская область / Павлодар |
| Улица / дом | улица Тестовая / 73 |
| Квартира / подъезд / этаж | 41 / 2 / 4 |

Пример синтетический: он показывает смешанный русский и казахский ввод, а не подтверждает существование здания. Неизвестные значения остаются `null`.

**Для проверки пакета** откройте [главную страницу](https://jana.linker.kz), вставьте несколько адресов — по одному на строку — или загрузите TXT, JSON, CSV, XLSX. Нажмите «Нормализовать пакет», откройте спорную запись, исправьте поля и нажмите «Подтвердить адрес». Задание сохраняется по ссылке и восстанавливается после обновления страницы; «Экспорт JSON» скачивает результаты.

Попробуйте отдельную строку `Караганда`: одно название совместимо с городом и селом. Интерфейс позволяет явно выбрать населённый пункт по справочнику.

## Скачать и запустить v0.2.0

[**Скачать релиз v0.2.0**](https://github.com/lukivan8/jana-locate/releases/tag/v0.2.0) — исходники, компактная CRF-модель и контрольные суммы. Для локального запуска нужны Docker Engine/Desktop с Compose v2, `make`, `curl` и `tar` (Linux, macOS или WSL).

```sh
curl --fail --location \
  https://github.com/lukivan8/jana-locate/releases/download/v0.2.0/jana-locate-v0.2.0-source.tar.gz \
  --output jana-locate-v0.2.0-source.tar.gz
tar -xzf jana-locate-v0.2.0-source.tar.gz
cd jana-locate-v0.2.0
make demo
```

Первая сборка скачивает зависимости и модели libpostal: подготовьте её до показа, с интернетом. Для работы стенда нужно около **4 GiB свободной памяти сверх Docker и ОС**. После сборки нормализация не требует подключения к публичному сайту.

| Что открыть | Локальный URL |
| --- | --- |
| Веб-интерфейс | [localhost:13008](http://localhost:13008) |
| HTTP API | `http://localhost:18088` |
| OpenAPI | [localhost:18088/openapi.json](http://localhost:18088/openapi.json) |

`make demo-status` показывает состояние, `make demo-stop` останавливает стенд с сохранением заданий и исправлений. [Повторный запуск без скачиваний](docs/hackathon-demo.md#локальный-запуск).

> Готовые контейнеры и установщик **v0.1.0** относятся к предыдущему выпуску без нового числового слоя. Для проверки актуального решения используйте сайт или сборку v0.2.0 выше. [Установка готовых контейнеров](docs/quickstart.md).

## Первый batch-запрос

Можно сразу вызвать публичный API из терминала с `curl`; скачивать проект для этого не требуется. Адреса будут отправлены на `jana.linker.kz`. Для автономной обработки используйте запущенный локальный API с тем же контрактом.

**1. Выберите API и скачайте его OpenAPI:**

```sh
JANA_API_URL=https://jana.linker.kz
curl --fail --retry 30 --retry-all-errors --retry-delay 2 "$JANA_API_URL/readyz"
curl --fail-with-body "$JANA_API_URL/openapi.json" --output openapi.json
```

Для локального v0.2.0 замените первую строку на `JANA_API_URL=http://localhost:18088`. Следующие команды выполняйте в том же терминале. В Postman можно импортировать скачанный `openapi.json`.

**2. Создайте `batch.example.json`:**

```sh
cat > batch.example.json <<'JSON'
{
  "records": [
    {
      "id": "test-1",
      "raw_address": "Павлодар, улица Тестовая, дом 73; 41 пәтер; 2 кіреберіс; 4 қабат"
    },
    {
      "id": "test-2",
      "raw_address": "Караганда"
    }
  ]
}
JSON
```

Это синтетические примеры. Для своей проверки замените строки, сохранив поля `id` и `raw_address`.

**3. Отправьте пакет и сохраните ответ:**

```sh
curl --fail-with-body --max-time 310 "$JANA_API_URL/v1/normalize" \
  --header 'Content-Type: application/json' \
  --data-binary @batch.example.json \
  --output batch-results.json
cat batch-results.json
```

Ответ `{"results":[...]}` содержит результат для каждой записи **в исходном порядке, с теми же ID и точными исходными строками**. У `test-1` будут квартира `41`, подъезд `2`, этаж `4`; у `test-2` — статус `needs_review` и предупреждение о неоднозначности населённого пункта.

Лимиты одного запроса: **1–1000 записей**, до **4096 байт UTF-8 на адрес**, тело до **2 MiB**. Передавайте ID строками, особенно большие числовые ключи. HTTP 200 означает, что пакет обработан; оценивайте поля, `status` и `warnings`. `confidence` — эвристическая оценка для приоритизации проверки, а не измеренная точность.

## Как устроено решение

```text
Свободный текст → libpostal → правила и КАТО/OSM → числовая CRF → HTTP JSON
                                                               ↓
                                              проверка оператором и экспорт
```

- **Согласование со справочниками Казахстана.** Названия и варианты сопоставляются с КАТО/OSM, согласуются населённый пункт и область, район дополняется по подготовленным свидетельствам. В снимке 66 339 сущностей и 1 078 711 адресных свидетельств; покрытие частичное.
- **Компактное числовое дополнение.** Собственная CRF-модель с весами около 211 КиБ дополняет пустые дом, квартиру, подъезд и этаж. Заполненные поля и географические кандидаты сохраняются; при отказе слоя остаётся основной разбор. Основную память системы занимает libpostal.
- **Сохранение неоднозначности.** Сервис не выбирает произвольный город или село с одинаковым названием. Оператор видит варианты и может явно выбрать сущность.
- **Полный процесс проверки.** Пакеты, исправления и экспорт доступны в браузере. Локальный CLI работает с файлами и PostgreSQL: исходная таблица читается, публикация в связанную таблицу выполняется явно, пароль БД остаётся локально.

## Проверки и ограничения

Релиз v0.2.0 проверен Go race-тестами и vet, сборкой и проверкой типов frontend, Python-тестами числового слоя и **49 браузерными сценариями**: 33 для frontend и 16 для CLI с PostgreSQL. Проверены desktop и 390×844, исправление и экспорт, сохранение данных после перезапуска, отказ числового сервиса и работа без внешней сети. [Подробности проверки](docs/hackathon-demo.md#проверки-выпуска).

География — **Казахстан**. Нормализация не выдаёт координаты и не подтверждает существование здания. `matched` означает полноту основных полей без выявленной неоднозначности. Независимая точность на реальных адресах пока не заявляется; демонстрационные примеры и оценки синтетические. [Результаты и ограничения числового слоя](docs/numeric-recovery-results.md).

У API нет встроенной авторизации. Для собственного публичного развёртывания нужны TLS, аутентификация и ограничения на шлюзе. [Развёртывание](docs/deployment.md).
