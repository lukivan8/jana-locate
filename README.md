# Jana Locate

**Превратите адресную строку в структурированные поля и подключите нормализацию к своему сервису по HTTP.** Jana Locate разбирает адреса Казахстана, сохраняет исходный ввод, показывает неизвестные поля и неоднозначности. Для проверки результатов есть веб-интерфейс, для файлов и PostgreSQL — локальный CLI.

[**Открыть приложение ↗**](https://jana.linker.kz) · [Быстрый запуск](#быстрый-запуск-готовые-контейнеры) · [Подключение API](docs/integration.md) · [Примеры кода](examples/http/README.md) · [Документация](docs/README.md) · [Сообщить об ошибке](https://github.com/lukivan8/jana-locate/issues/new/choose)

> [!TIP]
> **Организаторам: [запустите Docker API](#только-api--скачать-и-запустить-одной-командой), затем [отправьте batch JSON](#первый-batch-запрос-после-запуска).** OpenAPI запущенного контейнера: [`http://localhost:8080/openapi.json`](http://localhost:8080/openapi.json). Для знакомства в браузере доступен [jana.linker.kz](https://jana.linker.kz).

## Что можно сделать

| Задача | Как использовать Jana Locate |
| --- | --- |
| Нормализовать адрес при создании заказа | Вызвать `POST /v1/normalize` из своего backend |
| Обработать накопленные адреса | Отправлять пакеты до 1000 записей, сохраняя ID и порядок |
| Проверить спорные результаты | Открыть веб-интерфейс, исправить поля и экспортировать JSON |
| Обработать колонку PostgreSQL | Запустить локальный CLI: снимок → нормализация → проверка → явная публикация |
| Работать с файлами без БД | Передать текстовый или JSON-файл в CLI |
| Развернуть в закрытой сети | Заранее собрать образы; при работе загрузка моделей и внешние API не нужны |

Нормализация выделяет область, населённый пункт, район, жилой массив, улицу, дом и детали доставки. Например, из строки `Астана, проспект Туран 55/6 кв 99` извлекаются компоненты адреса; неизвестные значения остаются `null`. Конкретный результат зависит от режима парсера и снимка справочников.

## Как нормализуется адрес

На [jana.linker.kz](https://jana.linker.kz) работает пайплайн **libpostal + справочники Казахстана + компактная CRF-модель**:

1. **Подготовка.** Система сохраняет исходную строку и очищает рабочую копию от невидимых символов и лишних пробелов.
2. **Разбор.** libpostal выделяет компоненты адреса, а правила явных обозначений дополняют их по маркерам вроде `дом`, `кв`, `подъезд` и `этаж`.
3. **Справочники.** КАТО и OSM помогают сопоставить названия и их варианты, согласовать населённый пункт с областью и дополнить район по подготовленным связям улиц и домов. Неоднозначности передаются оператору вместе с результатом.
4. **Числовая модель.** Обученная на размеченных синтетических адресах CRF определяет по контексту дом, квартиру, подъезд и этаж. Проверенные предложения дополняют пустые поля, сохраняя результат основного разбора. Веса модели занимают около **211 КиБ**.
5. **Ответ.** API возвращает структурированные поля, оценку уверенности, статус и предупреждения с сохранением ID и порядка записей. Весь процесс работает офлайн на заранее подготовленных моделях и справочниках.

Например, в строке `Павлодар, улица Тестовая, дом 73; 41 пәтер; 2 кіреберіс; 4 қабат` основной разбор выделяет город, улицу и дом, а числовая модель дополняет **квартиру 41, подъезд 2 и этаж 4**. Пример синтетический.

## Быстрый запуск: готовые контейнеры

**Локальный Jana Locate полностью автономен.** Модели libpostal и справочники Казахстана уже включены в образ. После скачивания контейнеров обработка работает без интернета, hosted API, регистрации и внешних ключей. Go, Node.js, Python, Git и сборка исходников для установки не нужны.

Для API достаточно **Docker Engine или Docker Desktop**. Для комплектов с установщиком дополнительно нужны Compose v2, curl и shell. Текущий выпуск — **[0.1.0](https://github.com/lukivan8/jana-locate/releases/tag/v0.1.0)** для `linux/amd64`. На ARM используется эмуляция amd64 средствами Docker; нативный ARM-образ пока не выпускается.

### API + Web + CLI — комплект по умолчанию

```sh
curl -fsSL https://raw.githubusercontent.com/lukivan8/jana-locate/main/scripts/install.sh | sh -s -- full
```

Полный комплект включает автономный API на `http://localhost:8080`, встроенный веб-интерфейс на `http://localhost:8095` и CLI для файлов и PostgreSQL. Локальный интерфейс открывается без логина и пароля. PostgreSQL автоматически не устанавливается: можно подключить свою базу или работать с файлами. Порты по умолчанию доступны только на этой машине.

После установки в терминале появятся URL OpenAPI и команда batch-запроса, а в `jana-locate/` — готовый `batch.example.json`. [Проверить свои адреса через API →](#первый-batch-запрос-после-запуска)

```sh
cd jana-locate
./jana status      # состояние контейнеров
./jana down        # остановить с сохранением данных
./jana up          # снова запустить установленные образы, без скачивания и сборки
```

### Только API — скачать и запустить одной командой

```sh
docker run -d --name jana-locate --platform linux/amd64 \
  --restart unless-stopped -p 127.0.0.1:8080:8080 \
  -v jana-locate-api-data:/data \
  ghcr.io/lukivan8/jana-locate-api:0.1.0
```

Docker сам скачает готовый образ и запустит API на `http://localhost:8080`. Первый старт загружает модели в память; дождитесь успешного ответа `/readyz` перед отправкой адресов. Для этого пути не нужны Compose, Git, компиляторы, ключи внешних сервисов или подготовка моделей. Данные сохраняются в томе; остановка — `docker stop jana-locate`, повторный запуск — `docker start jana-locate`.

Если нужен единый launcher для управления контейнерами, используйте [установщик](docs/quickstart.md) в режиме `api`. [Исходник установщика](scripts/install.sh).

### Первый batch-запрос после запуска

Команды выполняются **на вашем компьютере**, рядом с Docker; клонировать репозиторий и заходить в контейнер не нужно. Понадобятся curl и shell (Linux, macOS или WSL).

**1. Дождитесь готовности и скачайте OpenAPI именно запущенного API:**

```sh
curl --fail --retry 30 --retry-all-errors --retry-delay 2 http://localhost:8080/readyz
curl --fail-with-body http://localhost:8080/openapi.json -o openapi.json
```

Контракт также можно открыть по [`http://localhost:8080/openapi.json`](http://localhost:8080/openapi.json) или импортировать этот URL/файл в Postman. В исходниках он лежит в [`backend/api/openapi.json`](backend/api/openapi.json).

**2. Создайте `batch.example.json` с несколькими адресами:**

Если использовали установщик, выполните `cd jana-locate` (или перейдите в выбранный каталог установки): пример уже лежит там, этот шаг можно пропустить.

```sh
cat > batch.example.json <<'JSON'
{
  "records": [
    {
      "id": "test-1",
      "raw_address": "Астана, проспект Туран 55/6 кв 99"
    },
    {
      "id": "test-2",
      "raw_address": "Алматы, улица Абая 10, подъезд 2, этаж 3"
    },
    {
      "id": "test-3",
      "raw_address": "Караганда"
    }
  ]
}
JSON
```

Примеры синтетические; последняя строка намеренно неоднозначна. Для своей проверки замените записи на тестовые адреса, сохранив поля `id` и `raw_address`.

**3. Отправьте файл и сохраните ответ:**

```sh
curl --fail-with-body --max-time 310 http://localhost:8080/v1/normalize \
  -H 'Content-Type: application/json' \
  --data-binary @batch.example.json \
  --output batch-results.json
cat batch-results.json
```

Это синхронный batch endpoint: ответ `{"results":[...]}` сразу содержит по одному результату на каждую запись в исходном порядке, с теми же `id` и `raw_address`. В установке через скрипт `batch.example.json` уже находится в каталоге `jana-locate/`, а команда печатается после запуска. Если меняли порт, замените `8080` в URL.

Для оценки качества сравните адресные поля из `results` со своим эталоном по ID/позиции. HTTP 200 означает успешную обработку, а `status`, `warnings` и `null` показывают полноту и неоднозначность; `confidence` не является измеренной точностью. **[Лимиты, поля результата и ошибки →](docs/quickstart.md#первый-batch-запрос-после-запуска)**

### Другие комплекты

Укажите `api` для одного нормализатора или `web` для API и отдельного веб-интерфейса на `http://localhost:3000`. Без аргумента установщик выбирает `full`.

### Hosted API — без локального нормализатора

Если размещать нормализатор у себя не требуется, вызывайте **`https://jana.linker.kz/v1/normalize`** с тем же JSON-контрактом. [Пример подключения к hosted API](docs/integration.md#локальный-и-hosted-api).

Локальный интерфейс/CLI можно использовать с hosted API:

```sh
curl -fsSL https://raw.githubusercontent.com/lukivan8/jana-locate/main/scripts/install.sh | sh -s -- hosted
```

Этот вариант скачивает только контейнер интерфейса/CLI и отправляет адреса на `jana.linker.kz`. Пароль PostgreSQL остаётся локально. Для полностью автономной обработки выбирайте `api`, `web` или `full`.

## Подключение к своему сервису

Jana Locate — отдельный HTTP-сервис. Выберите свой автономный экземпляр или hosted endpoint `https://jana.linker.kz`; формат запросов одинаков.  Ваше приложение отправляет адреса и получает JSON; ему не нужны Go, Node.js, доступ к исходникам или прямой доступ к справочнику.

```text
Ваш сервис ── POST /v1/normalize ──► Jana Locate
           ◄── поля, статус, предупреждения ──
```

- Передавайте ID строками, особенно если они превышают безопасный диапазон JavaScript.
- Сохраняйте исходный адрес вместе с результатом; `null` означает, что поле не определено.
- Направляйте `needs_review` и `unmatched` на проверку по правилам вашего продукта.
- `matched` означает полноту основных полей без выявленной неоднозначности. Это не подтверждение существования дома или географической позиции.
- `confidence` — эвристическая оценка для приоритизации проверки, а не измеренная вероятность правильного ответа.

**[Руководство подключения →](docs/integration.md)** · [JavaScript](examples/http/normalize.mjs) · [Python](examples/http/normalize.py) · [Go](examples/http/go/main.go) · [OpenAPI](backend/api/openapi.json)

## Проверка результатов в браузере

**[Открыть готовое приложение на jana.linker.kz →](https://jana.linker.kz)** Для локального запуска интерфейс доступен на `http://localhost:3000`.

![Интерфейс Jana Locate: импорт адресов и очередь проверки](docs/assets/workspace.png)

*Скриншот актуального приложения на синтетических адресах. Резервный режим без native libpostal явно показывает предупреждения.*

1. Вставьте строки или загрузите файл.
2. Выполните нормализацию и откройте требующие проверки записи.
3. Проверьте предупреждения, исправьте поля; при омонимах выберите населённый пункт явно.
4. Сохраните исправления и экспортируйте результат.

Пакет хранится как задание: его можно открыть по ссылке и продолжить после обновления страницы. Серверные задания хранятся до 7 дней после изменения; лимит — 50 заданий / 64 MiB. [Работа с интерфейсом](docs/web.md) · [API заданий](backend/docs/jobs.md).

## Локальная работа с файлами и PostgreSQL

```sh
cd jana-locate
./jana connect
./jana normalize
```

CLI поднимает API и встроенный сайт проверки; PostgreSQL пользователь подключает отдельно. Исходная таблица остаётся доступной только для чтения. По явной команде готовые результаты публикуются в отдельную связанную таблицу. Пароль базы не передаётся нормализатору. Адресные строки и временные позиционные ID отправляются на выбранный API.

Файловый режим не требует подключения к базе. Прогресс и правки хранятся в локальном SQLite-журнале. **[Руководство CLI →](cli/README.md)**

## Что важно знать перед внедрением

- **География — Казахстан.** Язык и письменность ввода не выбирают другую страну.
- **Геокодирование не входит в нормализацию.** Совместимые поля `coordinates`, `catalog_id`, `catalog_revision` у новых результатов равны `null`.
- **Покрытие справочников частичное.** Включены 66 339 сущностей КАТО/OSM и 1 078 711 адресных свидетельств без координат. Это не гарантия наличия каждого адреса страны. [Источники и покрытие](backend/docs/reference.md).
- **Неоднозначность сохраняется.** Одинаковое название города и села само по себе не позволяет выбрать одну сущность.
- **Точность на независимых реальных данных пока не заявляется.** Встроенные примеры и разметка синтетические.
- **У API нет встроенной авторизации.** Для доступа из внешней сети нужны TLS, аутентификация и ограничения на вашем шлюзе. [Развёртывание](docs/deployment.md).
- **Локальный сервис полностью автономен после скачивания образов.** Модели и справочники входят в контейнер; `jana.linker.kz` не нужен для его работы. Hosted API — отдельный выбор пользователя.
