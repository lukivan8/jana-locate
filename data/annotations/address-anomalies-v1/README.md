# LLM-разметка 2000 синтетических адресов

Отдельная разметка входов из `frontend/src/data/address-anomalies.json`.
Исходный набор и приложения не изменены. Нормализация, libpostal и проверка
качества текущего нормализатора не запускались.

Размечено **2000/2000** записей, выделено **13 265** фрагментов. Ориентиры есть
в **253** записях. После повторного просмотра всех **219** исходных замечаний
**188** проверок разметки закрыты, **31** остаётся с `review`. Повторения ориентиров
сохранены: всего **976** фрагментов `landmark`. Это количества разметки,
не показатели качества нормализации.

Покрытие районов дополнено отдельным набором
[`districts-v1`](../districts-v1/README.md): 240 новых строк и 16 спецификационных
сценариев справочного обогащения. Исходные 2000 входов и эта разметка не изменены.

## Файлы

- `annotations.jsonl` — основной результат, одна запись на вход, исходный порядок.
- `validation-report.json` — количества, перечень записей с `review`, выполненные
  структурные проверки.
- `review-audit.json` — все 219 исходных замечаний, решения повторного LLM-просмотра,
  сохранённые диагностики ввода и две явные поправки пропущенных названий улицы.
- `source-manifest.json` — SHA-256 исходного набора, происхождение и атрибуция.
- `shards/*.labels.jsonl` — явные решения LLM до вычисления позиций фрагментов.
- `shards/*.input.jsonl` — точные входы, удобная копия текста для чтения и
  публичная справочная подсказка из основы генерации.
- `INSTRUCTIONS.md` — единый протокол разметки.

Работа разделена между тремя субагентами (по 600 строк) и основным агентом
(200 строк). Каждый исполнитель прочитал свои записи и явно выбрал смысловые
фрагменты. Скрипты использованы для подготовки файлов, сериализации решений,
поиска позиций выбранного текста и структурной проверки. Семантические метки
не вычислялись regex, нормализатором или обращением генератора мутаций.
Дополнительно один субагент независимо проверил 200 строк основного агента
и первые 65 строк первой части; это не полная независимая проверка всего набора.
После запроса о закрытии неоднозначностей все 219 замечаний повторно
просмотрены тремя субагентами и основным агентом с обращением к местным
справочникам. Исходные решения частей сохранены; повторные решения применяются
как явный слой `review-audit.json`, без запуска семантического парсера.

## Формат основного результата

Запись содержит точные `id` и `raw_address`, массив `spans`, агрегированные
`fields`, причину `review` либо `null` и происхождение разметки.

Каждый фрагмент имеет `label`, `start`, `end`, `text`:

- `start` включительно, `end` исключительно, индексы Unicode code points в
  **исходной** строке, не UTF-8 байты и не JavaScript UTF-16 code units.
- `raw_address[start:end] == text` в Python. В JavaScript для индексации по
  code points сначала требуется `Array.from(raw_address)`.
- Фрагменты отсортированы по позиции и не пересекаются.
- Внутренние невидимые символы и исходные пробелы сохранены в `text`.

Метки: `province`, `city`, `district`, `living_area`, `street_type`,
`street_name`, `house`, `apartment`, `entrance`, `floor`, `landmark`,
`delivery_instruction`, `other`. `city` включает населённые пункты любого типа.

`fields` содержит массивы исходных фрагментов или `null`. Массивы позволяют
сохранить повторения, двуязычные названия, конфликтующие значения и разрывные
части имени. Это формат разметки, **не** контракт HTTP API нормализатора.
Части имени улицы, разделённые типом, могут быть отдельными `street_name` spans;
массив не обязательно означает несколько разных улиц.

Маркеры номера дома/квартиры/подъезда/этажа обычно не входят в числовой
фрагмент. Явный тип улицы выделен отдельно; неизвестный или отсутствующий тип
не восстановлен. Основной адрес в квартале/микрорайоне размечен как тип и имя,
дополнительный микрорайон при наличии улицы — как `living_area`.

Ориентир сохраняет отношение и объект: `за рынком Весна`,
`рядом с аптекой Лотос`, `напротив кафе Луч`. Инструкции вроде
`вход со двора` выделены отдельно. Повторённые ориентиры имеют отдельные spans.
Текст вне выделенных spans остаётся **неразмеченным**: это могут быть маркеры,
разделители или неоднозначный остаток. Перед обучением CRF нужно отдельно
согласовать токенизацию и политику меток для таких фрагментов; этот файл сам
по себе не является готовой обученной моделью или экспортом libpostal TSV.

## Справочники и неоднозначность

Использованы локальные KATO/OSM Казахстана и опубликованные основы
`frontend/src/data/address-bases.json` как справочные подсказки. Основа описывает
адрес **до** синтетических изменений и не считается ожидаемым ответом.
Отсутствующие город, область и дом не восстановлены из подсказки. Опечатки,
транслитерация, ошибочная раскладка и изменённые номера сохранены дословно.
Канонические названия и идентификаторы справочников не приписываются spans.

### Выбор LLM и поведение нормализатора

LLM может выбрать предпочтительную гипотезу, чтобы завершить разметку.
Для нормализатора правильным результатом также является явная неоднозначность.
Обучение не должно превращать выбор разметчика в обязательный единственный
ответ и подавлять другие допустимые разборы или справочные сущности.

Метка `city` означает населённый пункт любого типа. Например, в локальном КАТО
`Караганда` — и село (`kato:154247300`), и город (`kato:351010000`). Уверенное
извлечение строки `Караганда` не выбирает одну из этих сущностей. До появления
различающих сведений из ввода или выбора оператора совместимые кандидаты
должны сохраняться, а нормализатор должен подсвечивать неоднозначность.

Набор размечает фрагменты текста; географическая идентичность и все случаи её
неоднозначности здесь **не размечены**. Поэтому `annotation_status: resolved`,
`review: null` и отсутствие `input_issues` не являются целевыми метками
«однозначный адрес» или «не показывать предупреждение». `reference_hint.city_id`
и `source_base_id` описывают происхождение синтетики, а не единственно верный
объект для обучения. Село нельзя исключать только потому, что LLM выбрала
более известный город либо такой вариант чаще встречается в генерации.

Будущие обучение и оценка должны отдельно проверять извлечение фрагментов,
сохранение кандидатов-омонимов и ложные уверенные разрешения неоднозначности.
Нужны примеры одного имени для города и села, с различающим контекстом и без,
в разных языках и транслитерациях. Все мутации одной основы следует держать
в одной части train/validation/test, чтобы исключить утечку. Корректную подсветку
неоднозначности нельзя считать ошибкой за несовпадение с выбором LLM.

`annotation_status` разделяет `unflagged` (1781 запись без первоначальной
пометки), `resolved` (188 закрытых проверок) и `needs_review` (31 нерешённая
проверка). `review_category` даёт категорию повторного решения. `review`
теперь означает только нерешённую неоднозначность **разметки**, а
`input_issues` сохраняет отдельные диагностики противоречивого/неадресного ввода
и качества справочного источника. Выбранная интерпретация неоднозначной записи
остаётся гипотезой. Отсутствие `review` не означает подтверждение человеком.

В 177 из 188 закрытых случаев границы и роли фрагментов ясны, но во вводе
есть конфликт: области, населённые пункты, иерархия, дорожные типы, дома или
квартиры. Все явно написанные значения сохранены, правильное значение не
выбиралось. Остальные 11 закрытых случаев: пять пустых/неадресных строк,
два явных упоминания села, два placeholder-названия улицы, два необычных,
но явно обозначенных номера дома. В двух placeholder-строках дополнены
пропущенные spans `street_name`; качество источника остаётся диагностикой.

Открытые 31 случай: 2 неоднозначные роли чисел, 11 неоднозначных цифр в
`Рассветная8` рядом с другим домом, 10 слитных границ улица/дом и 8 совпадений
города с названием улицы. Наличие выбранного имени в неполном справочнике
не доказывает отсутствие других прочтений. Эти строки не следует включать
в однозначный обучающий/проверочный эталон без маскирования спорных фрагментов
либо дополнительного решения. Закрытые конфликтные строки подходят для
задачи извлечения всех компонентов, но не задают единственный правильный адрес.

Весь набор синтетический и размечен LLM (`human_verified: false`). Содержание
не представляет реальные проверенные доставки. Семантическая точность не
измерялась; отчёт проверяет полноту записей, сохранность исходного текста и
корректность координат фрагментов. Поскольку все 2000 строк размечены,
независимый тестовый набор для дальнейшего обучения/оценки потребуется
выделять отдельно, учитывая общие основы и семейства мутаций.

## Сборка без запуска нормализации

Из корня репозитория:

```sh
python3 scripts/assemble-address-annotations.py
```

Отдельную часть можно проверить через `--shard a` (также `b`, `c`, `d`).
Скрипт не определяет метки: он применяет явные решения повторного просмотра,
разворачивает текстовые выборки LLM в позиции исходной строки, проверяет
соответствие аудита первоначальным причинам `review`, SHA-256, ID, порядок,
наличие фрагментов и отсутствие пересечений. Изменение `.labels.jsonl` требует
повторной сборки основного результата.
