# Обозначения населённых пунктов, транслит и опечатки

76 размеченных примера для будущего обучения. Первые четыре сохраняют строки
пользователя и скриншота дословно: `г Караганда`, `город Караганда`, `Karaganda`,
`Караганды` с адресом `улица Алалыкина дом 12`.

- 48 вариантов для Караганды, Алматы, Астаны, Шымкента, Актобе и Костаная:
  полный/сокращённый маркер, слитное написание, транслит, казахские буквы,
  регистр, смешение кириллицы с латиницей внутри слова и опечатки.
- 8 названий без адресного контекста: Караганда и Актобе имеют несколько
  населённых пунктов в КАТО, и эта неоднозначность должна сохраняться.
- 8 отрицательных примеров: название другого города в ориентире, вывеске,
  инструкции или отрицании не становится городом назначения.

Ещё 12 вариантов покрывают казахские маркеры улицы после названия:
`көшесі`, `көш.`, `көш`, пользовательское `кош`, `кошеси`, `koshesi`;
порядок `12 үй` / `үй 12`, смешанное `дом12`, город в конце и отсутствие запятых.
Пример пользователя сохранён дословно под ID `settlement_variant_065`:
`Қарағанды, Алалыкин кош дом 12`. Разметка: city=`Қарағанды`,
street_name=`Алалыкин`, street_type=`кош`, house=`12`.

`кош` здесь — авторская интерпретация сокращённого/искажённого маркера улицы
по контексту, а не утверждение нормативного казахского написания.
`expected_canonical_street_type=улица` хранится отдельно от исходного span.
Сопоставление `Алалыкин` с реальной улицей `Алалыкина` не объявляется решённым:
`street_identity_resolution=not_performed`. Все 12 строк включены в существующее
семейство Караганда / Алалыкина / 12. Наблюдение 68% не является целевой уверенностью.

## Файлы и смысл меток

`inputs.json` — готовый пакет для импорта; `inputs.jsonl` — построчный ввод.
`cases.jsonl` содержит явные авторские выборки, `annotations.jsonl` — точные
spans и поля. Позиции заданы в Unicode code points, конец исключительно.
`coverage-report.json` описывает покрытие, `source-manifest.json` — источник
справочных названий и контрольные суммы ранее размеченных наборов.

В `город Караганда` city-span равен `Караганда`, без слова `город`.
В `Karaganda` city-span остаётся `Karaganda`: это буквальное извлечение текста.
Отдельное `expected_canonical_city` содержит авторскую гипотезу `Караганда`
для будущей канонизации. Оно не предписывает единственный справочный ID.
Гипотезы исправления опечаток также требуют будущей проверки и не оправдывают
уверенный выбор при конкурирующих интерпретациях.

`reference_ids` перечисляет одноимённые сущности Казахстана как контекст.
Фильтровать их можно по явному типу населённого пункта, административному
контексту и положительным адресным свидетельствам. Отсутствие записи улицы
или дома в неполном справочнике не доказывает отсутствия альтернативы.
У одиночной `Караганда` сохраняются город и село; язык не выбирает победителя.

Показанные пользователем 93%/88% сохранены в `user_observation` с
`is_training_target=false` и `reproduced=false`. Набор не задаёт требуемый
процент уверенности и не измеряет качество текущего нормализатора.

Все 76 записей считаются синтетическими/учебными; исходный адрес пользователя
служит примером, а существование и принадлежность остальных адресов не
утверждаются. Разметка LLM, без проверки носителями языков.

Девять семейств `family_id` должны оставаться целиком в одной части будущего
разбиения. Дополнительно необходимо объединить связанные основы с другими
наборами, особенно все варианты Караганда / Алалыкина / 12. Независимый
train/validation/test пока не сформирован.

Воспроизведение: `python3 scripts/assemble-settlement-variants.py`.
Скрипт сериализует явно заданные LLM-компоненты и находит их буквальные позиции;
он не использует regex для семантической разметки и не вызывает нормализатор.
