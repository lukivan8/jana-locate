# Синтетические адреса для будущего обучения

Текущий этап — подготовка и разметка данных. Дообучение libpostal и изменение
runtime не входят в сборку этих наборов. Сборщики применяют явные LLM-выборки
фрагментов; результаты нормализатора не используются как эталон разметки.

Все адреса относятся к Казахстану. Другой язык, транслитерация и названия
иностранных городов внутри ориентиров не меняют страну назначения.

| Набор | Записей | Назначение |
| --- | ---: | --- |
| [address-anomalies-v1](address-anomalies-v1/README.md) | 2000 | Исходные адресные аномалии и LLM-разметка |
| [districts-v1](districts-v1/README.md) | 240 | Районы, отрицательные примеры, конфликты и омонимы |
| [kazakhstan-multilingual-v1](kazakhstan-multilingual-v1/README.md) | 400 | Казахстанские адреса на разных языках, транслит и смешанное написание |
| [settlement-variants-v1](settlement-variants-v1/README.md) | 76 | Обозначения города, казахские маркеры улицы, транслит, опечатки и омонимы |

Итого 2716 записей, включая 716 дополнительных. Это число примеров,
а не независимых географических основ: часть языковых вариантов производна
от районного набора и помечена `origin`.

В `annotations.jsonl` каждого набора находятся исходная строка, текстовые
компоненты и их позиции в Unicode code points: `start` включительно,
`end` исключительно. Отсутствующий в строке район не получает span.
Район, который можно дополнить по улице/дому, относится к отдельной задаче
справочного обогащения; синтетический адрес не доказывает реальную связь.
16 сценариев этой задачи находятся отдельно в
[reference-enrichment-fixtures.json](districts-v1/reference-enrichment-fixtures.json).

Выбранная LLM гипотеза не устраняет неоднозначность. Сохраняются конфликты,
совместимые справочные альтернативы и различие города/села. `reference_ids`
служат контекстом, а не принудительным единственным ответом. Частота известного
города в синтетике не исключает одноимённое село.

Разметка синтетическая, silver, без проверки носителями языков. Она не является
оценкой качества текущего нормализатора. Перед будущим обучением следует
проверить языковую естественность и удерживать все варианты `family_id`,
связанные через `origin` основы и дубликаты в одной части разбиения.
Независимый train/validation/test пока не сформирован.

Проверка структуры и воспроизведение дополнительных наборов без запуска NLP:

```sh
python3 scripts/assemble-district-annotations.py
python3 scripts/assemble-kazakhstan-multilingual.py
python3 scripts/assemble-settlement-variants.py
```

Проверяются точность привязки spans к raw, отсутствие пересечений, ID,
отрицательные примеры, казахстанский справочный контекст и сохранность
контрольных сумм исходных данных.
