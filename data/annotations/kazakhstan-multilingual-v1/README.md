# Адреса Казахстана на языках пользователей

**География всех 400 примеров — Казахстан.** Кыргызский, узбекский, таджикский
и монгольский здесь описывают язык ввода, а не страну доставки. Справочные
населённые пункты и районы берутся только из локального КАТО Казахстана.
Зарубежный географический черновик удалён и в этот набор не входит.

Добавлены пять групп по 80 строк:

| Группа | Содержание |
| --- | --- |
| base | Ранее размеченные казахстанские районные основы с RU/KK/UZ и новыми явными дополнениями |
| ky | Кыргызские конструкции, транслит и смешанный ввод |
| uz | Узбекская латиница, кириллица, транслит и смешанный ввод |
| tg | Таджикская кириллица со специальными буквами, транслит и смешанный ввод |
| mn | Монгольская кириллица, транслит и смешанный ввод |

В сумме 339 строк имеют районные spans, 60 — отрицательные примеры без
адресного района, одна оставляет спорную роль неразмеченной. В 114 строках
выделены ориентиры, в 68 специально заложены диагностические свойства.
Районы и населённые пункты-омонимы сохраняются как разные кандидаты.

## Файлы

- `inputs.json` — отдельный пакет из 400 `{id, raw_address}`.
- `inputs.jsonl` — тот же ввод построчно.
- `annotations.jsonl` — фрагменты исходной строки, поля, язык, семейство,
  географическая область применения, справочные подсказки и диагностики сценария.
- `coverage-report.json` — количества и структурные проверки.
- `source-manifest.json` — явное уточнение области применения, методы авторства
  и контрольные суммы сохранённых наборов и казахстанского справочника.
- `shards/*.cases.jsonl` — авторские исходники и явные выборки разметки.
- `INSTRUCTIONS.md` — правила авторства и проверки языковых примеров.

Исходные 2000 адресов и дополнение из 240 районных адресов вместе с их
разметкой сохранены; сборщик проверяет их контрольные суммы. Новые строки
не добавлялись на frontend-страницу `/examples`. Формат HTTP API не изменён.

## География и текстовые роли

Казахстанские имена могут оставаться в исходном написании или транслитерироваться,
а окружающие слова меняться: `Алмалы району`, `Almaly tumani`,
`ноҳияи Алмалы`, `Алмалинский дүүрэг` описывают адрес в Казахстане. Такие
конструкции — синтетические пользовательские формулировки, а не утверждение
эквивалентности правовых административных уровней разных стран.

Названия `Бишкек`, `Душанбе`, `Монголия` и подобные могут встречаться только
в названии магазина/ориентира, улице или инструкции доставки. Их нельзя
переносить в `city`/`country` назначения. Язык и письменность не выбирают страну.
Область применения KZ задана пользователем, а не выведена из языка моделью.

Слово «Караганда»/«Қарағанды» по-прежнему может обозначать город либо село.
Закрытая разметка не даёт оснований удалять одну из сущностей или снимать
предупреждение нормализатора. `reference_ids` — контекст, не обязательные
единственные целевые ID. `expected_input_issues` описывает специально
созданные случаи, а пустой список не доказывает однозначность адреса.

Район, не написанный в строке, не получает span. Справочное обогащение по
улице/дому остаётся отдельным слоем. Геометрия, координаты зданий и реальная
принадлежность синтетических улиц районам не утверждаются.

## Авторство и использование

Группы ky/uz/tg созданы и размечены LLM по строкам. Группа base композиционно
использует уже выбранные LLM-фрагменты из `districts-v1`, сохраняя `origin`.
Для группы mn LLM явно задала типизированные компоненты и монгольские шаблоны;
скрипт `scripts/author-mongolian-kz-cases.py` составляет строки и селекторы из
этих компонентов. Это авторская генерация с известными ролями, не извлечение
меток нормализатором, regex или инверсией существующего парсера.

Все примеры синтетические, разметка silver. Носители языков их не проверяли.
Монгольская группа особенно шаблонная; набор нельзя считать реалистичным
распределением пользовательского потока или единственным материалом обучения.
Отдельная независимая языковая проверка нужна перед выводами о качестве модели.

100 семейств по четыре варианта. Варианты, их известные `origin` и языковые
версии одной исходной основы должны оставаться в одной части train/validation/test.
Иначе модель увидит тот же адрес в другой письменности и оценка будет завышена.
Независимое разбиение и проверка качества нормализатора здесь не выполнены.

Опциональная метка `co`/`country` используется только для явно написанного
Казахстана в наборе извлечения. Это локальное поле экспериментального датасета,
не добавление поля в текущий API. Отсутствие country-span не требует догадки.

## Воспроизведение

```sh
python3 scripts/author-mongolian-kz-cases.py
python3 scripts/assemble-kazakhstan-multilingual.py
```

Первый скрипт воспроизводит только авторскую типизированную монгольскую группу.
Второй применяет явные выборки, вычисляет позиции в Unicode code points
исходной строки и проверяет структуру, языковое покрытие, отрицательные
случаи, существование казахстанских ID и сохранность исходных файлов.
Нормализатор/libpostal не запускаются; текущая точность не измеряется.
