# Частые вопросы

[Документация](README.md)

## Нужен ли второй репозиторий Jana Address?

Нет. Jana Locate содержит API, интерфейс, CLI, контракт и документацию. Исторический Go module path сохранён для совместимости, но интеграция по HTTP не зависит от него.

## Можно ли использовать только API?

Да: `docker compose up --build --wait backend`. Веб-интерфейс и CLI не обязательны. [Подключение](integration.md).

## Есть ли готовые Docker-образы?

Публичные образы пока не выпускаются. Quick start собирает контейнеры из исходников. Сборка требует сети, runtime — нет.

## Почему coordinates равны null?

Текущая нормализация выделяет адресные поля и сохраняет неоднозначности. Геокодирование исключено; legacy-поля координат и каталога сохранены только для совместимости и у новых результатов равны `null`.

## Почему известный город требует проверки?

У названия может быть несколько совместимых справочных сущностей, например город и село. Популярность названия не устраняет омоним. Добавьте различающий контекст или явно выберите населённый пункт.

## Что означает confidence 0.9?

Это эвристическая оценка свидетельств и конфликтов. Она не означает измеренную точность 90%. Для внедрения проверяйте качество на независимых данных своей задачи, отдельно учитывая ложные уверенные решения и сохранение неоднозначности.

## Какие языки поддерживаются?

Назначение инструмента — адреса Казахстана. Обрабатываются русские/казахские формы и доступные варианты справочников; смешанные письменности, транслитерация и другие языковые случаи представлены в синтетических исследованиях. Полноценная измеренная поддержка каждого языка не заявляется. Язык не меняет страну назначения.

## Почему есть libpostal_unavailable?

API запущен без native libpostal, например через обычный `go run`. Работают правила и подготовленный справочник. Для полного режима используйте Docker или [native-сборку](../backend/docs/normalization.md).

## Интерфейс открылся, но запросы не работают

Проверьте `/readyz`, URL в `JANA_API_URL` и CORS. `backend:8080` обычно недоступен браузеру. При изменении порта сайта обновите точный origin в `CORS_ORIGINS`; при HTTPS сайта используйте HTTPS API. [Сетевые настройки](deployment.md).

## Можно ли открыть API в интернет?

После настройки TLS и аутентификации на своём шлюзе. Встроенной авторизации у нормализатора нет. Защитите также задания, исправления и legacy-endpoints. CORS не заменяет контроль доступа.

## Сервис получает пароль моей PostgreSQL?

API нормализации — нет. Локальный CLI хранит профиль подключения и отправляет выбранному API адресные строки и временные ID. Выбирайте размещение API с учётом характера адресных данных.

## Можно ли удалить контейнеры без потери работы?

`docker compose down` сохраняет тома. `down --volumes` удаляет их. Серверные задания имеют срок хранения, поэтому сохраняйте экспорт. CLI хранит отдельный журнал. [Хранение](deployment.md).

## Как сообщить об ошибке?

Создайте [issue](https://github.com/lukivan8/jana-locate/issues/new/choose) с синтетическим минимальным примером, режимом запуска и версией исходников. Не публикуйте реальные адреса, пароли и журналы клиентов. Для уязвимости используйте [закрытый канал](../SECURITY.md).
