# Развёртывание и эксплуатация

[Документация](README.md) · [Быстрый запуск](quickstart.md)

## Контейнеры

Корневой `compose.yaml` запускает Go API и необязательный статический frontend. API собирается только из `backend/`, frontend — только из `frontend/`. Node.js и Python при работе этих контейнеров не нужны. Браузер обращается напрямую к настроенному URL API.

```sh
docker compose up --build --wait backend  # API
docker compose up --build --wait          # API и интерфейс
docker compose ps
docker compose logs --tail=100 backend
```

Первый build загружает libpostal и зависимости. Runtime использует готовые локальные assets. Готовых публичных образов пока нет; для воспроизводимого развёртывания фиксируйте commit исходников и сохраняйте собранные образы.

## Порты и URL

Настройки корневого Compose задаются в `.env`, скопированном из [.env.example](../.env.example).

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `API_BIND_ADDRESS` | `127.0.0.1` | Интерфейс хоста для API |
| `API_PORT` | `8080` | Порт API на хосте |
| `WEB_BIND_ADDRESS` | `127.0.0.1` | Интерфейс хоста для сайта |
| `WEB_PORT` | `3000` | Порт сайта на хосте |
| `JANA_API_URL` | `http://localhost:8080` | URL API, доступный браузеру |
| `CORS_ORIGINS` | `http://localhost:3000` | Точные разрешённые origins через запятую |

Например, для других локальных портов:

```dotenv
API_PORT=18080
WEB_PORT=13000
JANA_API_URL=http://localhost:18080
CORS_ORIGINS=http://localhost:13000
```

Имя контейнера `backend` подходит для внутренней Docker-сети, но обычно недоступно браузеру. При HTTPS-размещении URL API тоже должен использовать HTTPS.

## Конфигурация API без корневого Compose

| Переменная | Назначение |
| --- | --- |
| `HTTP_ADDR` | Адрес прослушивания; по умолчанию `:8080` |
| `REFERENCE_PATH` | Подготовленный неизменяемый SQLite-справочник |
| `LIBPOSTAL_DATA_DIR` | Локальные модели native libpostal |
| `MODELS_REQUIRED` | `true` запрещает запуск без native libpostal; Dockerfile включает этот режим |
| `CATALOG_SEED_PATH` | Read-only seed legacy-каталога |
| `CATALOG_OVERLAY_PATH` | Записываемый файл legacy-каталога; также определяет соседнее хранилище заданий |
| `JOBS_PATH` | JSON-журнал серверных заданий; по умолчанию рядом с overlay |
| `CORS_ORIGINS` | Браузерные origins |

Путь хранения заданий и ограничения описаны в [API заданий](../backend/docs/jobs.md). `ALLOW_DEMO_CATALOG` не влияет на нормализацию. `GLINER_URL` текущему пайплайну не требуется.

## Данные и резервные копии

Справочник КАТО/OSM неизменяемый и отделён от рабочих данных. В корневом Compose записываемые файлы находятся в томе `catalog-data`, подключённом к `/data`. Рабочие задания могут содержать полные адреса и детали доставки.

- `docker compose down` сохраняет том.
- `docker compose down --volumes` удаляет его.
- Резервную копию записываемых файлов делайте при остановленном владельце, чтобы сохранить согласованное состояние.
- Не запускайте несколько API-процессов с одним записываемым overlay/хранилищем.
- Тесты выполняйте на отдельном временном томе.

[Legacy-каталог и восстановление](../backend/docs/catalog.md). CLI использует собственный том и SQLite-журнал; правила переноса описаны в [руководстве CLI](../cli/README.md).

## Внешний доступ

По умолчанию корневой стенд доступен только на loopback. У API нет встроенной аутентификации. Перед публикацией настройте reverse proxy или шлюз:

- TLS и проверку доступа;
- ограничения частоты, размера тела и числа параллельных запросов;
- таймауты для CPU-пакетов;
- защиту API сохранения заданий, правок и legacy-каталога;
- исключение адресных тел и секретов из логов.

CORS не заменяет авторизацию. Демонстрационный сайт должен использовать только синтетические данные; публичную демоверсию не следует использовать для рабочих адресов.

## Работа без внешней сети

В сети с доступом к зависимостям:

```sh
docker compose build
docker save jana-address-api:local jana-address-web:local -o jana-locate-images.tar
```

Перенесите архив и файлы Compose/.env в закрытое окружение:

```sh
docker load -i jana-locate-images.tar
docker compose up --no-build --pull never --wait
```

Для API без сайта достаточно образа API и запуска сервиса `backend`. Проверка репозитория `make offline-smoke` использует отдельную внутреннюю Docker-сеть и временные данные. Сам по себе перенос образов не отключает сеть — сетевую изоляцию задаёт окружение.

## Обновление

Зафиксируйте используемый commit, сделайте резервную копию рабочих данных, прочитайте изменения контракта и пересоберите образы. Для обновления запустите `docker compose up --build --wait`. Сохранённые результаты старых заданий не пересчитываются автоматически новой версией алгоритма.

Совместимость HTTP зависит от OpenAPI; версия схемы справочника — отдельная характеристика. При обновлении справочника переносите manifest и связанные файлы вместе, выполняйте `make reference` и перезапускайте API. [Справочник](../backend/docs/reference.md).
