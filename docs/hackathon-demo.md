# Jana Locate v0.3.0 — показ на хакатоне

Адреса Казахстана → структурированные поля → проверка спорных записей → JSON.
Действующий публичный стенд: [jana.linker.kz](https://jana.linker.kz).

## Локальный запуск

Нужны Git, Docker Engine/Desktop и Compose v2. Сборка скачивает зависимости,
модели libpostal и базовые образы. Заранее выполните её с интернетом: первая
сборка долгая. Компактная CRF-модель и справочный снимок включены в исходники.

```sh
git clone --branch v0.3.0 https://github.com/lukivan8/jana-locate.git
cd jana-locate
make demo
```

Интерфейс: `http://localhost:13008`, API: `http://localhost:18088`,
контракт: `http://localhost:18088/openapi.json`. Порты доступны только локально.
Для показа требуется около 4 GiB свободной памяти сверх Docker и ОС.

После первой сборки стенд можно поднять без скачиваний:

```sh
API_PORT=18088 WEB_PORT=13008 JANA_API_URL=http://localhost:18088 \
  CORS_ORIGINS=http://localhost:13008 docker compose -p jana-hackathon \
  -f compose.yaml -f compose.numeric.yaml up --no-build --pull never --wait
make demo-status
make demo-stop
```

Остановка сохраняет задания и исправления. Этот Compose-проект использует
отдельный том и не обращается к рабочим данным публичного стенда.
Для запуска без сборки используйте [установщик готового комплекта v0.3.0](quickstart.md).
Он включает API, числовую модель и интерфейс/CLI. Команды выше нужны для работы из исходников.

## Сценарий на 3–5 минут

1. Откройте «Разобрать адрес» и отправьте
   `Карагандинская область, город Сарань, улица Жамбыла 63, кв 123`.
   Покажите выделенные поля, статус, предупреждения и время HTTP-запроса.
2. Покажите числовой слой на синтетическом примере:
   `Павлодар, улица Тестовая, дом 73; 41 пәтер; 2 кіреберіс; 4 қабат`.
   Квартира, подъезд и этаж дополняют основной разбор.
3. На главной странице вставьте пакет из этих двух строк и `Караганда`.
   Запустите нормализацию. Одинаковое название города и села сохраняет
   неоднозначность; выбор населённого пункта делает оператор.
4. Откройте результат, исправьте квартиру и подтвердите адрес.
   Обновите страницу: задание и исправление сохраняются.
5. Нажмите «Экспорт JSON». Покажите исходную строку, ID, поля и предупреждения.
   На странице API покажите batch-контракт и скачивание OpenAPI.

Все приведённые адреса демонстрационные. Не подтверждайте существование зданий
по этим примерам. Нормализация не выдаёт координаты, не обещает покрытие всех
адресов и не скрывает неизвестные значения. Confidence — эвристика, а не
измеренная точность. Синтетические оценки описаны в
[отчёте числового слоя](numeric-recovery-results.md).

## Состав выпуска

Backend, независимый HTTP-only frontend и локальный CLI для файлов/PostgreSQL.
Основной pipeline: libpostal → правила и КАТО/OSM → компактное числовое дополнение.
Работа после подготовки образов не требует облачного AI или внешних ключей.

Удалён неиспользуемый экспериментальный Python runtime contextual v7 вместе
с отдельной Compose-конфигурацией, его browser-тестом и недоступными весами.
Удалены неподключённая карта координат, её геометрия и CSS. Контракт и Go-адаптер
сохранены для совместимости ранее записанных результатов и внешних клиентов.
Исходники до очистки сохранены тегом
`snapshot-before-hackathon-cleanup-20261018`. Приватные данные, локальные модели
экспериментов, журналы и резервные копии в релиз не входят.

## Проверки выпуска

18 октября 2026: `make generate`, `make check` (Go race/vet, frontend build/typecheck,
синхронизация контрактов и встроенного UI), 4 Python-теста числовых признаков,
33 Playwright-сценария против отдельного Docker API с временным хранилищем.
Проверены desktop 1440×1000 и mobile 390×844: разбор, неоднозначность,
исправление, восстановление задания и JSON-экспорт.
`make cli-smoke` прошёл 16 browser-сценариев с PostgreSQL, публикацией и
перезапуском. `make smoke` и `make offline-smoke` проверили batch из 1000 строк и сохранение
данных после перезапуска. Отказ числового сервиса проверен с сохранением native
результата. Проверки подтверждают работу сценариев, а не точность на реальных адресах.
