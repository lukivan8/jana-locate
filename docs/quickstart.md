# Установка готовых контейнеров

[Документация](README.md) · [Подключение API](integration.md)

## Попробовать онлайн

**[Откройте Jana Locate → jana.linker.kz](https://jana.linker.kz)**. Для знакомства с приложением ничего устанавливать не нужно. Можно также вызывать hosted API по `https://jana.linker.kz/v1/normalize`.

## Только API: одна команда установки

Нужны Docker Engine/Desktop с Compose v2, curl и shell:

```sh
curl -fsSL https://raw.githubusercontent.com/lukivan8/jana-locate/main/scripts/install.sh | sh -s -- api
```

Установщик скачивает готовые образы API и числовой модели и запускает их вместе.
API — `http://localhost:8080`, готовность — `/readyz`. Модели и справочники уже внутри.
Остановить: `cd jana-locate && ./jana down`; снова запустить: `./jana up`.
Данные сохраняются в томе. В комплекте v0.3.1 локальный API включает тот же
числовой CRF-слой, что публичный стенд.

## Первый batch-запрос после запуска

Команды выполняются **на вашем компьютере**, рядом с Docker; клонировать репозиторий и заходить в контейнер не нужно. Понадобятся curl и shell (Linux, macOS или WSL).

**1. Дождитесь готовности и скачайте OpenAPI именно запущенного API:**

```sh
curl --fail --retry 30 --retry-all-errors --retry-delay 2 http://localhost:8080/readyz
curl --fail-with-body http://localhost:8080/openapi.json -o openapi.json
```

Контракт также можно открыть по [`http://localhost:8080/openapi.json`](http://localhost:8080/openapi.json) или импортировать этот URL/файл в Postman. В исходниках он лежит в [`backend/api/openapi.json`](../backend/api/openapi.json).

**2. Создайте `batch.example.json` с несколькими адресами:**

Если использовали установщик, выполните `cd jana-locate` (или перейдите в выбранный каталог установки): пример уже лежит там, этот шаг можно пропустить.

```sh
cat > batch.example.json <<'JSON'
{
  "records": [
    {
      "id": "test-1",
      "raw_address": "Астана, проспект Туран 55/6 кв 99"
    },
    {
      "id": "test-2",
      "raw_address": "Алматы, улица Абая 10, подъезд 2, этаж 3"
    },
    {
      "id": "test-3",
      "raw_address": "Караганда"
    }
  ]
}
JSON
```

Примеры синтетические; последняя строка намеренно неоднозначна. Для своей проверки замените записи на тестовые адреса, сохранив поля `id` и `raw_address`.

**3. Отправьте файл и сохраните ответ:**

```sh
curl --fail-with-body --max-time 310 http://localhost:8080/v1/normalize \
  -H 'Content-Type: application/json' \
  --data-binary @batch.example.json \
  --output batch-results.json
cat batch-results.json
```

Это синхронный batch endpoint: ответ `{"results":[...]}` сразу содержит по одному результату на каждую запись в исходном порядке, с теми же `id` и `raw_address`. В установке через скрипт `batch.example.json` уже находится в каталоге `jana-locate/`, а команда печатается после запуска. Если меняли порт, замените `8080` в URL.

В одном запросе: **1–1000 записей**, до **4096 байт UTF-8 на адрес**, до **2 MiB на всё тело JSON**. Большой файл разбейте на пакеты, соблюдая оба лимита. Не отправляйте поля эталонного ответа вместе с входом: endpoint принимает записи `id`/`raw_address`. Поддерживается и массив `[{"id":"...","raw_address":"..."}]` на верхнем уровне; для него ответ тоже массив.

### Как проверить качество

Сравните поля каждой записи `results` с эталоном организаторов по исходному `id` (при повторяющихся ID — по позиции). Основные поля: `province`, `city`, `district`, `living_area`, `street_type`, `street_name`, `house`; детали: `apartment`, `entrance`, `floor`, `landmark`. Неизвестные значения — `null`.

- HTTP 200 подтверждает обработку пакета, но не правильность всех полей.
- `status`: `matched` — основные поля заполнены без выявленной неоднозначности; `needs_review` — нужна проверка; `unmatched` — недостаточно данных для разбора.
- `warnings` объясняет ограничения и неоднозначность. Например, `libpostal_unavailable` означает резервный режим: такой прогон не следует принимать за проверку полного native-парсера готового образа.
- `confidence` — эвристика для очереди проверки, не процент точности. Долю правильных ответов считайте по независимому эталону; синтетический пример выше эталоном не является.

`POST /v1/normalize` не создаёт сохраняемое задание: результат остаётся в вашем `batch-results.json`. OpenAPI описывает полный ответ; [руководство API](../backend/docs/consumer-guide.md) — поля и поведение.

### Если запрос не прошёл

| Симптом | Что проверить |
| --- | --- |
| Не удаётся подключиться / `/readyz` ещё не отвечает | Первый старт загружает модели. Дождитесь готовности; смотрите `./jana logs` |
| HTTP 400 | Валидность JSON, наличие `id` и строкового `raw_address`, число записей и длину адресов |
| HTTP 413 | Уменьшите пакет: тело превышает 2 MiB |
| HTTP 415 | Передайте заголовок `Content-Type: application/json` |
| curl завершился с ошибкой | Проверьте код завершения и тело `batch-results.json`: там может быть ошибка API вместо `results` |

## Установить локально одной командой

Нужны Docker Engine/Docker Desktop с Docker Compose v2, curl и POSIX shell (Linux, macOS или WSL). Go, Node.js, Python, Git и подготовка моделей не требуются. Публикуются образы `linux/amd64`; ARM-хостам нужна поддержка эмуляции amd64 в Docker. Нативный ARM пока не проверен и не выпускается.

По умолчанию устанавливается полный комплект **API + Web + CLI** (`full`). Для специального сценария можно явно выбрать другой режим:

| Комплект | Что запускается | Адрес |
| --- | --- | --- |
| `full` (по умолчанию) | Автономный API, CLI и встроенный веб-интерфейс | `http://localhost:8095` |
| `api` | Автономный API | `http://localhost:8080` |
| `web` | Автономный API и отдельный веб-интерфейс | `http://localhost:3000` |
| `hosted` | Локальный CLI/интерфейс, нормализация через jana.linker.kz | `http://localhost:8095` |

```sh
curl -fsSL https://raw.githubusercontent.com/lukivan8/jana-locate/main/scripts/install.sh | sh -s -- full
```

Без аргумента устанавливается тот же комплект `full`. Для другого режима замените последний аргумент на `api`, `web` или `hosted`. Установщик скачивает опубликованные образы, создаёт `./jana-locate/` и запускает Docker Compose **без сборки исходников**. [Исходник установщика](../scripts/install.sh).

После запуска установщик печатает URL OpenAPI и команду отправки `batch.example.json` в API с сохранением `batch-results.json`. Пример лежит в каталоге установки; существующий файл не перезаписывается. [Формат и оценка результата](#первый-batch-запрос-после-запуска).

Изображения скачиваются из GHCR; если реестр недоступен без авторизации, установщик использует публичные архивы того же [релиза 0.3.1](https://github.com/lukivan8/jana-locate/releases/tag/v0.3.1) и проверяет SHA-256. Учётная запись GitHub для этого пути не нужна.

API-образ включает модели libpostal и справочники: архив этого релиза занимает около 817 MiB. Дополнительное место потребуется для загруженного Docker-образа и рабочих томов. Первый старт загружает их в память; ожидайте готовности. API ограничен 3 GiB RAM и двумя CPU в Compose. Для полного комплекта нужен дополнительный запас памяти Docker и свободного диска. Эти значения — настройки контейнеров, а не измеренные минимальные требования.

## Автономность

**Комплекты `api`, `web`, `full` полностью автономны после скачивания.** Парсер, модели, справочники и сохранение рабочих данных находятся локально. Runtime не загружает модели и не обращается к hosted API, онлайн-геокодерам или внешней LLM. Запуск `./jana up` использует только уже установленные образы.

Режим `hosted` выбран явно: он требует интернета и отправляет адресные строки на `https://jana.linker.kz`. Пароли вашей БД туда не передаются. [Подключение к обоим вариантам](integration.md#локальный-и-hosted-api).

## Управлять установкой

```sh
cd jana-locate
./jana status
./jana logs
./jana down
./jana up
```

Остановка сохраняет Docker-тома. `./jana compose down --volumes` удаляет данные — для обычной остановки используйте `./jana down`. Настройки хранятся в `.env` с ограниченными правами. В `full`/`hosted` локальный сайт открывается без логина и пароля.

Для CLI:

```sh
./jana connect
./jana normalize
./jana normalize --help
```

База PostgreSQL устанавливается отдельно. На обычном Linux CLI использует host network и может подключиться к `localhost` вашей базы. Docker Desktop использует bridge: для базы на компьютере укажите `host.docker.internal`. `JANA_NETWORK_MODE=bridge` позволяет выбрать bridge явно до установки.

## Другие порты и каталог

Переменные задаются до запуска установщика. При передаче через pipe они должны относиться к `sh`, например:

```sh
curl -fsSL https://raw.githubusercontent.com/lukivan8/jana-locate/main/scripts/install.sh | \
  JANA_INSTALL_DIR="$HOME/jana-test" JANA_PROJECT_NAME=jana-test JANA_API_PORT=18080 JANA_WEB_PORT=13000 sh -s -- web
```

Для нескольких независимых установок задавайте разные `JANA_PROJECT_NAME`, каталоги и порты. Для полного комплекта порт сайта задаёт `JANA_CLI_PORT`. Повторная установка сохраняет `.env` и данные; смена комплекта останавливает прежний комплект, не удаляя тома. Порты, браузерный URL API и CORS после установки меняются в `.env` согласованно.

## Загрузка в закрытую сеть

Скачайте нужные архивы `jana-locate-<api|numeric|web|cli>-0.3.1-linux-amd64.tar.gz` и их `.sha256` из [релиза](https://github.com/lukivan8/jana-locate/releases/tag/v0.3.1). Перенесите их, файлы Compose, launcher и `.env` в закрытую сеть. Проверьте SHA-256, выполните `docker load -i <архив>` для каждого образа и запустите `./jana up`. Интернет для работы локальных комплектов не нужен. [Подробности](deployment.md).

## Сборка из исходников — для разработки

Это дополнительный путь, а не обязательный этап установки:

```sh
git clone https://github.com/lukivan8/jana-locate.git
cd jana-locate
cp .env.example .env
docker compose up --build --wait
```

Go 1.23+, Node.js 22.12+ и Python 3 нужны только для разработки вне контейнеров. [Backend](../backend/README.md) · [Frontend](../frontend/README.md) · [CLI](../cli/README.md).
