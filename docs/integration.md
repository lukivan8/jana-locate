# Подключение к своему сервису

[Документация](README.md) · [Запуск](quickstart.md) · [Полный контракт](../backend/api/openapi.json)

## Схема подключения

Разверните Jana Locate рядом со своим приложением. Ваш backend отправляет JSON на `/v1/normalize`, получает результат и применяет свои правила проверки. Фронтенд Jana Locate и CLI для этой интеграции не обязательны. Доступ к вашей БД API нормализации не требуется.

Начните с `http://localhost:8080` из [быстрого запуска](quickstart.md). Для другого контейнера `localhost` означает сам контейнер: используйте DNS-имя API в общей Docker-сети. Для браузера нужен URL, доступный с машины пользователя, и точный разрешённый CORS origin.

## Локальный и hosted API

Контракт одинаков для двух вариантов:

| Вариант | Базовый URL | Автономность |
| --- | --- | --- |
| Свой контейнер | `http://localhost:8080` или URL вашего экземпляра | Полностью автономный runtime; адреса обрабатываются в вашем окружении |
| Hosted API | `https://jana.linker.kz` | Нужен интернет; адресные строки передаются hosted-сервису |

```sh
curl --fail-with-body https://jana.linker.kz/v1/normalize \
  -H 'Content-Type: application/json' \
  -d '{"records":[{"id":"order-1","raw_address":"Астана, проспект Туран 55/6 кв 99"}]}'
```

Примеры JavaScript/Python/Go переключаются переменной `JANA_API_URL=https://jana.linker.kz`. Из собственного backend можно вызывать hosted API без установки контейнера. Для локального интерфейса/CLI с hosted-нормализацией выберите комплект `hosted` в [установщике](quickstart.md); CLI отправляет HTTP-запросы с сервера, поэтому браузерный CORS не мешает этому сценарию. Прямой вызов из произвольного браузерного origin требует согласованного CORS и не обещается автоматически.

## Запрос

```sh
curl --fail-with-body http://localhost:8080/v1/normalize \
  -H 'Content-Type: application/json' \
  --data-binary @examples/http/request.json
```

Файл [request.json](../examples/http/request.json):

```json
{
  "records": [
    {"id": "order-1", "raw_address": "Астана, проспект Туран 55/6 кв 99"}
  ]
}
```

`records` содержит 1–1000 записей. ID — строка или int64; для межъязыковой интеграции рекомендуются строки. Дубликаты разрешены: сопоставляйте результаты по позиции, если ID не уникальны. Исходный адрес обязателен, может быть пустой строкой и сохраняется без изменений.

Ограничения: 4096 байт UTF-8 на адрес и 2 MiB на тело запроса. Большие наборы разбивайте на пакеты. Помимо объектной формы поддерживается массив записей на верхнем уровне; ответ тогда тоже является массивом. Примеры используют объектную форму.

## Ответ и решение вашего приложения

Каждая запись в `results` содержит исходные `id` и `raw_address`, 11 адресных полей, `status`, `confidence`, `warnings` и совместимые legacy-поля. [Сохранённый полный ответ](../examples/http/response.fallback.json) получен от этой версии в резервном режиме; это пример формата, а не эталон качества native-парсера.

| Поля | Что делать |
| --- | --- |
| `province`, `city`, `district`, `living_area` | Хранить определённые значения; `city` обозначает любой населённый пункт, включая село |
| `street_type`, `street_name`, `house` | Хранить как строки: номер дома может содержать дробь или литеру |
| `apartment`, `entrance`, `floor`, `landmark` | Относить к исходной записи/доставке, а не к зданию по умолчанию |
| `confidence` | Использовать для приоритизации проверки; не интерпретировать как доказанную вероятность |
| `warnings` | Сохранять диагностику и показывать причины проверки оператору |
| `coordinates`, `catalog_id`, `catalog_revision` | У новых результатов нормализации всегда `null`; не ожидать геокодирования |

| Статус | Смысл | Типичное действие |
| --- | --- | --- |
| `matched` | Основные поля заполнены, значимая неоднозначность не обнаружена | Применить собственные правила допустимости |
| `needs_review` | Есть неполнота, конфликт, неоднозначность или предупреждения | Предложить проверку |
| `unmatched` | Недостаточно данных для содержательного разбора | Запросить уточнение или проверить вручную |

Не заменяйте неизвестные поля догадками. `matched` не подтверждает существование здания, право доставки или точность геопозиции. Обработанный адрес и подтверждённый оператором адрес — разные состояния вашего продукта.

Омонимы сохраняются: например, одинаковое название города и села не позволяет автоматически выбрать город. Для ручного выбора используйте `/v1/normalize/candidates` и `/v1/normalize/selections`; подробности в [справочнике API](../backend/docs/consumer-guide.md).

## Примеры для вашего языка

Все примеры запускаются из корня клонированного репозитория и используют только стандартную библиотеку/runtime. Они проверяют HTTP-ответ, количество результатов и сохранение входа, затем печатают JSON.

```sh
JANA_API_URL=http://localhost:8080 node examples/http/normalize.mjs
JANA_API_URL=http://localhost:8080 python3 examples/http/normalize.py
JANA_API_URL=http://localhost:8080 go run examples/http/go/main.go
```

[Исходники и требования](../examples/http/README.md). Текущий Go SDK находится в `backend/pkg/client`; исторический module path пока сохранён. Для актуальной версии используйте исходники этого репозитория или HTTP-пример. Отдельный `go get ...@latest` из старого репозитория не гарантирует соответствие текущему API.

## Таймауты, ошибки и повторы

Обработка синхронная и может занимать время, особенно для больших CPU-пакетов. Серверный бюджет ответа — 300 секунд. Подберите размер пакета и таймаут своего клиента и reverse proxy по измерениям. В примерах клиент ждёт до 300 секунд; транспортная задержка может потребовать дополнительного запаса.

| Ситуация | Действие |
| --- | --- |
| 400 | Исправить структуру или значения; не повторять тот же запрос бесконечно |
| 403 | Проверить Origin/CORS, если запрос пришёл из браузера |
| 413 | Уменьшить тело запроса |
| 415 | Передать `Content-Type: application/json` |
| 409 в операциях выбора/правок | Перечитать актуальную версию; согласовать изменение |
| Сетевая ошибка или 5xx | Ограниченный повтор с задержкой после проверки причины |

Ошибки обработчиков: `{"code":"...","message":"..."}`. Для 404/405 и ошибок шлюза тело может быть текстовым или HTML; сначала проверяйте HTTP-статус.

`POST /v1/normalize` не сохраняет результат в задания и не меняет каталог. Его можно повторить после транспортной ошибки, но байтовая идентичность ответа при обновлении алгоритма или справочника не обещается. Эти правила не следует автоматически переносить на POST сохранения исправлений и публикацию в БД.

## Сохранение и проверка

Если нужен управляемый сервером процесс проверки, используйте [API заданий](../backend/docs/jobs.md). Если у вашего продукта уже есть журнал и ревизии, храните результаты и исправления в нём; синхронный endpoint не требует создавать задания Jana Locate.

CLI хранит снимки и правки локально и отдельно публикует результат в PostgreSQL. Пароль БД не передаётся API, но адресные строки передаются на выбранный endpoint: учитывайте это при выборе места размещения.

## Перед внешним доступом

В API нет встроенной авторизации. Разместите его за TLS-шлюзом с аутентификацией, ограничениями размера/частоты запросов и подходящими таймаутами. CORS ограничивает браузерные origins, но не защищает API от серверных клиентов. Адреса и HTTP-тела не должны попадать в публичные логи.
