# Контекстный нормализатор v7: результаты подготовки выпуска

Дата: 17 октября 2026. Кандидат: `contextual-v7-grounded-microalpha-lean-v1`.
Использованы накопленные улучшения contextual v7, native numeric fusion, microdistrict head и
справочные слои. Последний экспериментальный ранжировщик не включён из-за регрессий.

Baseline снят непосредственно с API, обслуживавшего jana.linker.kz до переключения, а не взят
из старого лабораторного отчёта. Сравнены одинаковые 4488 входов в 14 наборах и отдельно ещё
24 примера заключительной проверки. ID, порядок и точные исходные строки сохранены.
На 4488/4488 результатов полностью совпали внутренние выделения, альтернативы, кандидаты и
диагностика упакованного сервиса и выбранного лабораторного v7. Представление Go API дополнительно
показывает общее каноническое имя, когда оно одинаково у всех кандидатов, не выбирая их идентичность.

## Примеры пользователя

- `г Караганда`, `город Караганда`, `Karaganda` с `улица Алалыкина дом 12` дают город Караганда,
  улицу Алалыкина, дом 12. Совпадение отображаемого имени не устраняет город/село из кандидатов.
- `Қарағанды, Алалыкин кош дом 12`: город и улица выделены отдельно, дом 12; `кош` остаётся
  исходным значением типа улицы. Полная канонизация всех языковых форм не завершена.
- `... д. 19, за рынком Весна, кв 34`: ориентир целиком `за рынком Весна`, дом 19, квартира 34.
- `Almaty, Kurilskaya 9 kv1`: улица, дом 9 и квартира 1 выделены; географическая неоднозначность
  не разрешается принудительно, написания Almaty/Kurilskaya могут сохраняться.
- `Астана, Kenesary 20, 4`: дом и квартира null; `Астана, Kenesary 20 4`: дом `20 4`, квартира null.
  Этот класс пока не исправлен. Диагностика и статус требуют проверки, числа не выданы за
  доказанную пару дом/квартира.

## Ресурсы и эксплуатация

Полный HTTP-запрос с 1000 существующих примеров: **89,49 секунды**, квота 2 CPU, лимит 300 секунд.
Baseline обработал ту же тысячу суммарно за 1,77 секунды в четырёх запросах по 250.
Форма пакетов различается, но новый NLP-проход явно существенно медленнее; лимит задачи он соблюдает.
Контейнер inference ограничен 4 GiB RAM и достиг этого лимита; в конце замера использовал ещё
около 82 MiB swap. Максимум Go API — 866 MiB. Пики компонентов не обязательно одновременны.
Это всё ещё тяжёлый runtime; большое снижение максимальной памяти относительно 5 GiB пока
не доказано. Подтверждённая ранее экономия — около 343 MiB памяти готового процесса модели
за счёт удаления неиспользуемых справочных объектов. Память и размер файлов не смешиваются.

При перегруженном хосте один предварительный прогон превысил native timeout. После завершения
параллельных тяжёлых проверок полный повторный прогон прошёл без OOM и без этого таймаута.
Это не гарантия работы при произвольной конкуренции и максимальной длине каждого адреса.

Дополнительная диагностика даёт около 23 MB JSON на 1000 примеров. В исходниках Go SDK и CLI
лимит ответа увеличен с 16 до 128 MiB, таймаут Go SDK — с 60 до 300 секунд; тесты проверяют
ответы больше прежнего лимита. Старым клиентам может требоваться обновление или меньший пакет.

До калибровки `confidence_available=false`, `confidence=0` — совместимый placeholder.
Интерфейс показывает «Не оценена»; все новые автоматические результаты пока `needs_review`.
Проверка оператором работает отдельно. Сохранённые старые задания не пересчитываются сами.

## Обнаруженные и исправленные ошибки интеграции

- Недоступный inference больше не выглядит успешным пустым результатом или пустым списком городов:
  синхронный вызов получает 503, фоновое задание — failed.
- Для списка городов завершённого задания используются сохранённые доказательства его разбора.
  Это просмотр рабочего журнала, а не поиск ответа на новый запрос нормализации по ID/строке.
- Повторные/одновременные запросы сериализуются через ограниченную очередь:
  один работает, ещё до трёх ожидают не более 150 секунд. Переполнение возвращает 503.
- Не загружается вторая native модель в Go API. Assets входят в контейнер и проверяются SHA-256;
  inference в showcase находится во внутренней сети, runtime не скачивает данные.
- Справочная версия учитывает версию нормализатора; старый выбор оператора не применяется
  незаметно к новому набору кандидатов. Ручной выбор и справочное дополнение района сохраняются.

Подробные машинные результаты локально: `.artifacts/contextual-release/comparison.json`,
`transitions.jsonl`, `original-corpus-metrics.json`, `prospective-comparison.json`,
`benchmark1000-final.json`, `user-probes.json`, журналы проверок.
Откат и подготовка образов: [инструкция развёртывания](contextual-deployment.md).

## Проверки готовности

- `make generate`, `make check`: синхронизация контрактов, race-тесты, vet, сборка и typecheck.
- `make smoke`: временный native стенд, пакет 1000, сохранение и повторный запуск.
- `make cli-smoke`: актуальные исходники CLI, временный PostgreSQL, restart/export/publication,
  сохранность int64/NULL/исходных строк и 16 браузерных сценариев.
- 33 существующих frontend-сценария в native режиме прошли с повтором после ошибок запуска стенда.
- 6 сценариев контекстного режима прошли на desktop и 390×844 после исправления интеграции:
  два окна, выбор/смена города, старые ревизии, сохранение/восстановление правок, экспорт доказательств,
  отсутствие ложных 0% и извлечение полного ориентира.
- Публичная проверка пакета и скриншоты фиксируются отдельно в `public-check.json` и browser-artifacts.

## Проверка после переключения jana.linker.kz

Публичный `POST https://jana.linker.kz/v1/normalize` через curl: **1000 адресов за 89,70 секунды**,
1000/1000 ответов точно совпали с проверенным API. Отдельный запрос текущим Go SDK также прошёл.
На сайте проверены отправка пакета и раскрытие результата: ориентир `за рынком Весна`, дом 19,
квартира 34, «Не оценена» вместо 0%. Desktop 1440×1000 и mobile 390×844: нет ошибок console,
ошибок страницы, framework overlay или горизонтального переполнения документа; таблица имеет
собственную горизонтальную прокрутку. PNG просмотрены и сохранены в browser-artifacts.

Обнаружено отдельное ограничение публичного шлюза: стандартный Python-urllib получает
Cloudflare 403 / code 1010 до обращения к origin. Curl, Go SDK и браузер проходят. Настройки
Cloudflare в этом выпуске не менялись; это не ошибка разбора адреса и не повод менять разметку.
