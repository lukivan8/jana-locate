# План развития

[Документация](README.md)

Этот список отделяет доступные возможности от планов. Сроки и гарантии реализации не заявляются.

## Доступно сейчас

- Готовые контейнеры 0.3.2, установка одной командой, автономные комплекты и выбор hosted API.
- HTTP-нормализация одиночных адресов и пакетов.
- Native libpostal, правила и подготовленный КАТО/OSM без runtime-загрузок.
- Явные неизвестные поля, предупреждения и неоднозначности.
- Веб-проверка, сохранение исправлений, экспорт и серверные задания.
- Локальный CLI для файлов и PostgreSQL, журнал и явная публикация.
- Контракт OpenAPI и независимые приложения в одном репозитории.

## Ближайшие направления

1. Расширение поддерживаемых платформ контейнеров и автоматизация проверки релизов.
2. Проверяемая совместимость версий API, CLI и справочников.
3. Независимый набор оценки реальных адресов с законным основанием публикации/обработки и без частных данных в репозитории.
4. Измерения качества извлечения полей, сохранения неоднозначности и ложных уверенных решений.
5. Измерения CPU-производительности и рекомендации по размеру пакетов.
6. Улучшение языковых вариантов и покрытия справочника по результатам оценки.

## Требуют отдельного проектирования

Встроенная авторизация, несколько писателей рабочего хранилища, полноценный аудит действий и геокодирование. Эти возможности нельзя считать частью текущего нормализатора.

Предложения принимаются через [issues](https://github.com/lukivan8/jana-locate/issues/new/choose). Воспроизводимый пример и описание пользовательской задачи полезнее неподтверждённой общей оценки точности.
